# Autism Gaming

2D-пиксельная игра на Godot 4.7.2 Standard / GDScript.

## Object Builder

**Сложность — внутри. Простота — снаружи.**

Создавать игровые объекты должно быть так же просто, как собрать конструктор: выбрать внешний вид, добавить нужные возможности, настроить, попробовать и использовать. Пользователю не обязательно знать устройство Godot или программировать.

Цель Object Builder — единый универсальный конструктор, где простой режим включён по умолчанию, а технические инструменты остаются доступны в расширенном режиме. Категория объекта помогает начать, но не ограничивает его возможности.

**Текущая версия: Object Builder 0.7.0.** Библиотека содержит 200 механик в 20 разделах. 40 имеют готовое runtime-поведение, остальные 160 уже описаны и доступны для поиска, но пока отключены до реализации компонентов. В карточках показывается статус; незавершённую механику нельзя включить.

Инструкция по текущей версии: [addons/object_builder/README.md](addons/object_builder/README.md).

**Каталог:** [MECHANICS_CATALOG.md](MECHANICS_CATALOG.md) — полный список 200 механик с описаниями и статусами.

**Актуальная дорожная карта:** [OBJECT_BUILDER_ROADMAP.md](OBJECT_BUILDER_ROADMAP.md) — фазы, задачи, зависимости и критерии готовности от 0.7.0 до 1.0 и далее.

## Запуск
Открой project.godot через Godot Project Manager и нажми F5.

## Редактирование карты
Открой scenes/world.tscn и выбери слои под Terrain.

| Слой | Содержимое |
|---|---|
| Ground | Сезонная трава, земля, песок, почва, вода, лёд и дорожки |
| Farming | 16 культур по 5 стадий |
| Fences | Один TileSet с четырьмя стилями заборов/стен |
| Decorations | Мелкий декор |
| AssetLibraries | Остальные библиотеки ассетов |

У забора один TileSet и четыре независимых Terrain Set: дерево, тёмный, белый и камень. Каждый стиль использует собственный AtlasSource с 16 соединениями. Выбирай нужный Terrain Set в слое Fences, автосоединение — через Terrains → Connect.

Размер клетки — 16×16. Сезон меняется параметром Season корневого узла Terrain. Для рисования отключи Scene Paint Mode (B), выбери TileMapLayer и пользуйся нижней панелью TileMap: Paint, Line, Rectangle, Bucket Fill, Select, Picker.

## Как размещать объекты
Готовые сцены генерируются плагином в res://scenes/environment_assets/. В Godot раскрой эту папку в панели FileSystem. Бери файлы .tscn, не исходные PNG.

Открой scenes/world.tscn, разверни World → Objects. Перетащи сцену из FileSystem в 2D-окно или на соответствующую группу:
- Nature — деревья, кусты, камни, растения;
- Buildings — дома, теплица, сарай, магазины;
- Props — сундуки, бочки, фонари и декор;
- Interiors — мебель;
- Animals — животные;
- Characters — NPC;
- Beach_Fishing — лодки, пляжные объекты и рыбалка;
- Effects — визуальные эффекты.

После добавления выбери объект инструментом Select/Move (Q) и передвинь. Сцены привязаны нижним центром, сортируются по Y и содержат коллизию там, где она нужна. Исходные PNG напрямую не перетаскивай.

### Выбор отдельного спрайта из PNG-листа

1. Выбери экземпляр дерева, включи у него **Editable Children** и открой дочерний `Visual` (Sprite2D).
2. Назначь PNG в свойство **Texture**.
3. Для одинаковых ячеек используй **Hframes / Vframes** и **Frame Coords** (счёт начинается с нуля).
4. Для произвольного фрагмента включи **Region → Enabled** и задай **Region Rect**: X, Y, Width и Height.

Меняй параметры у экземпляра, размещённого на карте: обновление каталога Cozy Village может заново сгенерировать исходные сцены деревьев и камней.

Если environment_assets пустая, проверь Project → Project Settings → Plugins → Cozy Village & Farm Tools → Enable и дождись первого импорта. Плагин создаёт сцены локально; на GitHub хранятся исходники и генератор. Для новых ассетов запусти Project → Tools → Cozy Village & Farm: обновить каталоги и сцены.

### Настройка спрайтшитов игрока

У каждой анимации игрока (Idle, Walk, Run, Sitting и боевые действия) отдельно задаются **Columns** и **Rows**, а также **Frames Per Direction**. Сетка может иметь любое количество строк и столбцов.

Главное поле — **Direction Layout**. В обычных случаях массивы вводить не нужно:

| Режим | Как расположены кадры |
|---|---|
| **Legacy 4 Rows** | Старый формат: вниз, вверх, вправо, влево. Сохраняет совместимость со старыми листами |
| **8 Rows** | Каждое из восьми направлений занимает отдельную строку; кадры идут слева направо |
| **8 Columns** | Каждое направление занимает отдельный столбец; кадры идут сверху вниз |
| **Direction Blocks** | Направления идут блоками подряд слева направо и автоматически продолжаются на следующих строках сетки |
| **Custom** | Только для действительно нестандартного порядка: вручную задаются стартовые индексы в массиве Direction Frame Starts |

Порядок восьми направлений: Down, DownRight, Right, UpRight, Up, UpLeft, Left, DownLeft.

**Пример: все 8 направлений по одному кадру в одной строке.** Выбери Direction Layout = Direction Blocks, Columns = 8, Rows = 1, Frames Per Direction = 1.

**Пример: все 8 направлений по 4 кадра в одной строке.** Выбери Direction Layout = Direction Blocks, Columns = 32, Rows = 1, Frames Per Direction = 4.

**Пример: 8 направлений отдельными строками, по 4 кадра.** Выбери Direction Layout = 8 Rows, Columns = 4, Rows = 8, Frames Per Direction = 4.

**Пример: 8 направлений отдельными столбцами, по 4 кадра.** Выбери Direction Layout = 8 Columns, Columns = 8, Rows = 4, Frames Per Direction = 4.

Для Idle есть отдельное поле **Idle Frames Per Direction**; значение 0 использует старое **Idle Frame Count**. Для Sitting применяется **Sitting Frames Per Direction**.

**Sitting** — отдельный спрайтшит с собственными Columns, Rows, Direction Layout, Frames Per Direction и Flip H. Он воспроизводится, когда игрок удерживает Ctrl и стоит на месте. При движении с Ctrl продолжает использоваться Walk с пониженной скоростью. Если Sitting Sheet не назначен, используется Idle.


## Коллизии
Вода и глубокая вода блокируют движение; береговые углы блокируют водную часть. Лёд и мосты проходимы. Деревья блокируют у ствола, камни — внизу, здания — по основанию, заборы — по соединениям. Цветы, трава и ковры не блокируют игрока.

## Управление
- WASD / стрелки — движение; Shift — бег; Ctrl — присесть; Space — перекат.
- 1–9 — слоты; B — инвентарь; Esc — настройки.
- F3 — Debug Inspector; F2 — журнал; ЛКМ/ПКМ — атака; Q — выбросить предмет.

В Debug Inspector:
- Окно разделено на две колонки: слева список объектов, справа параметры выбранного объекта. Заголовок можно перетаскивать; размер, прозрачность и положение настраиваются через значок шестерёнки и сохраняются локально.
- Список объектов по умолчанию показывает ближайшие к игроку объекты в радиусе 600 px и сортирует их по расстоянию: ресурсы, выброшенные предметы, а также размещённые постройки, мебель и декор из групп мира. Фильтр «Рядом» можно отключить, чтобы увидеть весь список. Обычные объекты можно выбирать кликом по спрайту или коллизии; для них доступны координаты, масштаб, поворот и Z-слой.
- В верхней строке есть выбор любого занятого слота быстрого доступа или рюкзака. Выбранный предмет можно исследовать и менять прямо из инвентаря — выбрасывать его в мир не требуется.
- Кнопка «Сохранить в базу» записывает все изменения выбранного предмета в его категорийный `.tres`-файл. Она доступна как для предмета из инвентаря/быстрых слотов, так и для выброшенного предмета. У отдельных изменяемых характеристик есть собственная кнопка «В базу».
- В настройках игры отдельно регулируется масштаб HUD, быстрых слотов и окон (70–140%). Масштаб самого окна дебага настраивается независимо (50–150%).
- «+ Предмет» открывает список всех зарегистрированных предметов и количество для создания предметов возле курсора.
- В инвентаре и на панели быстрого доступа показываются одинаковые подсказки с описаниями предметов.
- Масштаб выбранного игрового объекта в инспекторе задаётся в процентах (100% — исходный размер).
- Выброшенные игроком предметы нельзя подобрать в течение 0,9 секунды; их радиус притяжения магнитом уменьшен до 35% от обычного.

## Каталоги предметов

Данные предметов находятся в `data/items/` и разделены по категориям: `tools.tres`, `weapons.tres`, `food.tres`, `materials.tres`, `ammunition.tres`. Это текстовые Godot Resources, поэтому их удобно редактировать в Inspector или обычным текстовым редактором.

Каждый каталог содержит список `ItemDefinition`: ID, название, описание, категория, иконка, размер стопки, дополнительные свойства и боевые характеристики. Боевые характеристики из каталогов инструментов и оружия автоматически передаются в боевую систему. Инструменты и оружие всегда имеют размер стопки 1: несколько штук создаются как несколько отдельных объектов мира.

Кнопка «В базу» у характеристики сохраняет только её, а «Сохранить в базу» — все изменения выбранного предмета в исходный .tres-файл категории через ResourceSaver. Режим отладки нужен только для изменения значений — сама игра загружает каталоги при каждом запуске и использует их без включённого Debug Inspector. Файл `food.tres` уже содержит предметы с иконками; эффекты употребления еды ещё не реализованы.

Подробная структура и инструкция добавления предметов: `data/items/README.md`.

## Настройка атак и разрушаемых объектов

### Точка атаки игрока

В `scenes/world.tscn` раскрой `World → Player → AttackPivot`. Это отдельный узел `Node2D`: его **Position** задаёт общую точку начала ближней атаки. От неё рассчитывается попадание, и к ней прикрепляется затухающий след удара. Поэтому след движется вместе с игроком, пока отображается. Узел можно перемещать в 2D-окне или менять координаты в Inspector; код редактировать не нужно.

### Деревья и камни

Выбери размещённый объект `ResourceNode` в `scenes/environment_assets/Nature/` и открой Inspector:

- **Процедурный пень → Stump Height** — высота оставшейся части ствола после рубки; **Stump Width** — ширина. Пень рисуется процедурно, исходная текстура дерева после падения скрывается.
- **Звуки → Дерево** — массив `Tree Hit Sounds` (случайный звук попадания) и `Tree Destroy Sound` (падение дерева).
- **Звуки → Камень** — массив `Rock Hit Sounds` и `Rock Destroy Sound` (разрушение камня).

В поля звуков можно назначить любые подходящие `AudioStream`-ресурсы из проекта. Пустые поля означают тишину. При попадании также создаются пиксельные частицы: их основной цвет автоматически берётся из текстуры ударяемого объекта. Полосы здоровья над деревьями и камнями больше не отображаются.

Эти свойства хранятся на самом `ResourceNode` и уже доступны каждому экземпляру в Inspector. Это основа для будущего конструктора объектов; сам конструктор и сохранение наборов пресетов пока не реализованы.

## Object Builder — конструктор игровых объектов

В проект добавлен отдельный редакторский плагин Object Builder 0.3.1. Он создаёт определения игровых объектов и сохраняет их в библиотеку; игровой runtime не зависит от включённого плагина.

Плагин находится в правом доке Godot. Можно создать пустой объект с корневым типом Node2D, StaticBody2D, Area2D, CharacterBody2D, RigidBody2D или AnimatableBody2D либо создать копию встроенного/пользовательского шаблона. Для объекта задаются название, категория, теги, описание и пользовательские свойства типов String, Integer, Float, Boolean и Vector2. У каждого свойства можно повторно изменить подпись, тип, значение по умолчанию, группу и описание без смены его постоянного ID. Для Integer/Float доступны минимум и максимум с проверкой значения по умолчанию перед сохранением. При первом сохранении создаётся базовая сцена, которую можно открыть и дополнить обычными узлами Godot.

Дополнительные свойства можно помечать флагом «Дополнительный параметр»; пока это только метка в списке, сворачивание/скрытие расширенных настроек будет добавлено позже. Runtime API проверяет типы значений, использует default для неправильных overrides и ограничивает числовые значения min/max. Значения задаются отдельно для экземпляра и не меняют библиотечное определение; сохранение overrides в сцене/savegame и UI-инспектор экземпляра будут добавлены отдельно.

Библиотека поддерживает режимы «Все объекты», «Избранное» и «Недавние», а также фильтрацию по категориям и тегам. Избранное и последние 20 объектов сохраняются в локальных проектных метаданных редактора и не коммитятся в Git. Встроенное дерево показывает структуру открытой сцены выбранного объекта; в нём можно выбрать узел, добавить распространённый 2D-узел или удалить дочерний. При выборе Sprite2D отображается его текстура и основные настройки: HFrames/VFrames, Frame, Offset, Centered и Flip H/V. Для AnimatedSprite2D доступны SpriteFrames, список анимаций, выбор кадра, предпросмотр кадра и Speed Scale. Эти операции входят в штатную Undo/Redo историю редактора. Для сохранения самой сцены нажми Ctrl+S.

Флажок «Сохранить как шаблон» сохраняет новую заготовку отдельно от каталога игровых объектов. При создании копии сцены шаблона создаётся независимый файл, чтобы изменения нового объекта не меняли сам шаблон.

Данные хранятся раздельно:
- data/object_library/objects — определения;
- data/object_library/templates — встроенные и пользовательские шаблоны;
- data/object_library/scenes — сцены объектов;
- scripts/object_system — runtime-фабрика, реестр и контракты.

Категории можно вводить самостоятельно. Постоянный ID объекта не следует менять после того, как на него начнут ссылаться игровые сцены или сохранения. Перед перезаписью определения создаётся последняя резервная копия .bak.

Для создания объектов из кода можно добавить ObjectRegistry в дерево сцены и вызвать instantiate_by_id(object_id, parent). Пользовательские значения доступны через ObjectFactory.get_custom_property(), ObjectFactory.get_custom_property_definition() и ObjectFactory.set_custom_property(). Последний метод возвращает bool: неправильный тип или неизвестный ID отклоняется, а числовое значение вне min/max ограничивается диапазоном.

Плагин пока не мигрирует существующие деревья/камни и не заменяет Debug Inspector. Текущий этап и следующие задачи описаны в ROADMAP.md и ARCHITECTURE.md.
