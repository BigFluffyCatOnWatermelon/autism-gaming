# autism-gaming

Браузерная 2D-игра в пиксельном стиле. Работаем небольшими итерациями: ChatGPT меняет исходники в GitHub, пользователь запускает и проверяет проект в StackBlitz.

## Ссылки

- GitHub: https://github.com/BigFluffyCatOnWatermelon/autism-gaming
- Запустить в StackBlitz: https://stackblitz.com/github/BigFluffyCatOnWatermelon/autism-gaming

## Технологии

- Phaser 4.2.1
- JavaScript ES modules
- Vite 8.3.5
- StackBlitz WebContainers

На компьютер пользователя ничего устанавливать не нужно.

## Запуск

1. Открыть ссылку StackBlitz выше.
2. Дождаться импорта репозитория и установки зависимостей.
3. Дождаться запуска `npm run dev`.
4. Открыть Preview, если он не открылся автоматически.

Команды: `npm run dev`, `npm run build`, `npm run preview`.

## Часто меняемые параметры

В первую очередь смотри `src/config/gameConfig.js`. Значения сгруппированы по категориям:

- `world` — размер мира, количество деревьев и камней;
- `player` — скорости, здоровье, выносливость и физическое тело;
- `camera` — плавность, zoom и тряска;
- `dodge` — перекат;
- `weapons` — урон, типы урона, дальность, перезарядка и множители по ресурсам;
- `inventory` — хотбар, вместимость рюкзака и стрелы;
- `debug` — параметры отладки;
- `pixelArt` — размеры процедурной графики.

Не дублируй эти числа в игровых системах или UI.

## Графика

Первая версия использует оригинальные пиксельные текстуры, генерируемые кодом в `src/game/utils/PixelArt.js`. Сторонние ассеты пока не скачивались. Для каждого внешнего набора в будущем добавляй автора, ссылку и лицензию в `public/assets/LICENSES.md`. Предпочтительны CC0 и лицензии с явным разрешением на коммерческое использование.

## С чего начинать в новом чате

Перед работой обязательно прочитать:

1. `README.md`
2. `AGENTS.md`
3. `PROJECT_STATE.md`
4. `TASKS.md`
5. Последние записи `CHANGELOG.md`

После этого сверить документацию с реальными файлами GitHub. Не полагаться на память прошлого чата, не повторять уже выполненную работу и не считать непроверенный код рабочим.

## Правила работы

- GitHub — источник истины о коде.
- StackBlitz — браузерная среда запуска и проверки.
- Перед изменениями изучать относящиеся к задаче исходники.
- Делать небольшие, связанные с задачей изменения.
- Не переписывать работающие части без необходимости.
- После каждой задачи обновлять `PROJECT_STATE.md`, `TASKS.md` и `CHANGELOG.md`.
- Не утверждать, что тест или сборка пройдены, если их фактически не запускали.
- Не добавлять сторонние графические и звуковые ресурсы без проверки лицензии.
- Не хранить секреты и токены в публичном репозитории.
