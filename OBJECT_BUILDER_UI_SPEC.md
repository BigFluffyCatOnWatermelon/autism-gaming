# Object Builder — полная спецификация интерфейса (UI Specification)

**Главный тезис: «Сложность — внутри. Простота — снаружи».**

**Назначение:** детально зафиксировать будущие экраны, панели, вкладки, кнопки, списки, карточки, поля, меню, контекстные действия, состояния и поведение элементов. Документ предназначен для реализации и проверки интерфейса, а не только для объяснения концепции.

**Статус:** целевая спецификация с отмеченным текущим срезом реализации. Object Builder 0.8.0-dev содержит 200 механик: 42 доступны для включения, 158 имеют статус «В разработке». В рабочем пространстве уже реализованы LibraryView с карточками и компактным списком, фильтры категорий/тегов, избранное, недавние, шаблоны, пользовательские коллекции, поиск по возможностям, контекстные сведения и операции над записями. Реализованы Canvas и визуальный Preview черновика. Полная навигация деревом категорий, расширенные фильтры/сортировка, импорт сцен, мастер создания, игровые тестовые действия Preview и часть экспертных инструментов остаются целевым дизайном.

**Платформа:** Godot 4.7.2, первый полноценный вариант — 2D. Будущее расширение до 3D не должно усложнять первую версию.

Связанные документы:
- OBJECT_BUILDER_DESIGN_SPEC.md — продуктовые принципы и общая архитектура.
- OBJECT_BUILDER_WORKFLOW.md — сценарии пользователя.
- OBJECT_BUILDER_ROADMAP.md — актуальные фазы, задачи и критерии готовности.
- ARCHITECTURE.md — внутреннее устройство и текущий статус.
- ROADMAP.md и OBJECT_BUILDER_SYSTEM_PLAN.md — исходные авторские документы, сохранённые без переписывания.

Если старый макет расходится с этой спецификацией, в вопросах UI приоритет имеет данный документ. Архитектурные и технические решения описаны в DESIGN_SPEC и ARCHITECTURE.

# I. Принципы и общие правила

## 1. Главный путь пользователя

Обычный пользователь проходит один и тот же понятный путь:

1. Создать объект.
2. Добавить внешний вид.
3. Выбрать возможности.
4. Настроить их понятными параметрами.
5. Попробовать объект.
6. Сохранить и добавить в игру.

Он не должен начинать с выбора Node2D, CollisionShape2D, Component Binding, NodePath, сигналов или GDScript. Плагин сам подготавливает нужную техническую структуру.

## 2. Два режима

### 2.1. Простой режим — основной

Включён по умолчанию. Пользователь видит:
- обычные названия и короткие описания;
- большие карточки с иллюстрациями;
- визуальное поле;
- список выбранных возможностей;
- только относящиеся к ним настройки;
- Preview и понятные сообщения.

Не показывать:
- классы Godot и внутреннее дерево сцены;
- Component Type, Component Binding, Runtime Instance;
- NodePath и служебные ID;
- технические словари и массивы;
- необходимость вручную соединять сигналы;
- обязательное написание кода.

Простой режим не ограничивает каталог возможностей. Он скрывает реализацию, а не функциональность.

### 2.2. Расширенный режим

Переключатель «Расширенные инструменты» открывает дерево сцены, компоненты и их привязки, все свойства и их типы, связи, коллизии, sockets, состояния, события, зависимости и GDScript.

Оба режима редактируют один объект. Переключение режима не копирует данные и не меняет их семантику.

### 2.3. Уровни параметров

- **Основные** — видны сразу.
- **Дополнительные** — раскрываются кнопкой «Дополнительные настройки».
- **Экспертные** — доступны в расширенном режиме.

Это не последовательные страницы мастера. Пользователь открывает сложность только тогда, когда она ему нужна.

## 3. Обязательное поведение любого элемента

Каждый элемент управления должен:
- иметь понятное название или подпись;
- показывать доступное/недоступное состояние;
- иметь tooltip, если назначение неочевидно;
- быть доступным для клавиатурного фокуса;
- поддерживать Undo/Redo, если изменяет объект;
- объяснять причину блокировки, когда это неочевидно.

Важные действия никогда не должны быть спрятаны только за непонятной иконкой. Кнопки «Создать», «Сохранить», «Попробовать», «Добавить возможность» имеют видимый текст.

## 4. Визуальная система

- Карточки каталогов используют единый вид: изображение, название, краткое описание, статус.
- Числа показывают единицы измерения, если они применимы.
- Ползунок всегда сопровождается точным числовым полем.
- Переключатели имеют текст «Включено/Выключено» или понятный вопрос.
- Цвет не является единственным индикатором статуса: вместе с цветом есть текст и значок.
- Списки имеют понятное пустое состояние.
- Разрушительные действия визуально отделены.
- Подсказки дополняют подписи, но не заменяют их.

## 5. Горячие клавиши

| Действие | По умолчанию | Область |
|---|---|---|
| Сохранить | Ctrl+S | Конструктор |
| Отменить | Ctrl+Z | Конструктор |
| Повторить | Ctrl+Y / Ctrl+Shift+Z | Конструктор |
| Дублировать | Ctrl+D | Библиотека/расширенный редактор |
| Удалить | Delete | Выделенный удаляемый элемент |
| Поиск | Ctrl+F | Текущий список или каталог |
| Закрыть диалог | Esc | Диалоги и меню |
| Открыть библиотеку | Alt+1 | Object Builder |
| Попробовать | Не назначена | Конструктор |
| Переключить режим | Не назначена | Конструктор |

Сочетания настраиваются. Нельзя перехватывать ввод, пока пользователь печатает в текстовом поле, и нельзя конфликтовать с основными командами Godot без явного согласования.

# II. Общая оболочка Object Builder

## 6. Тип окна и раскладка

Object Builder открывается в отдельной главной вкладке Godot, а не в узком боковом dock.

Поддерживаются:
- изменение размеров панелей;
- сворачивание боковых областей;
- скрытие контекстного инспектора;
- восстановление стандартной раскладки;
- сохранение пользовательской раскладки;
- масштаб интерфейса;
- компактное поведение при узкой ширине.

### 6.1. Размеры диалоговых окон

Обязательное правило для любого окна Object Builder: верхняя панель, содержимое и нижние кнопки должны оставаться внутри доступной рабочей области монитора.

- Все окна открываются через единый метод безопасного показа; нельзя вызывать неограниченное центрирование напрямую.
- Максимальная ширина и высота рассчитываются относительно рабочей области текущего монитора с запасом под системные панели.
- Размер окна не должен превышать доступную область; при недостатке места оно уменьшается и центрируется.
- Длинные списки и формы помещаются в прокручиваемые области; нижние кнопки подтверждения/отмены остаются видимыми.
- Правило распространяется на мастер создания, выбор шаблона, свойства, настройки возможностей, выбор текстур/SpriteFrames, добавление узлов, Preview, подтверждения и все будущие диалоги.
- FileDialog также ограничивается доступной областью, но сохраняет собственные списки и навигацию.
- При открытии на другом мониторе размер вычисляется заново для его рабочего разрешения.
- В ручной приёмке проверить минимум 1280×720, 1366×768, 1920×1080 и экран с уменьшенной рабочей областью из-за системной панели. Это не заменяет проверку на реальном DPI-масштабе.

## 7. Глобальная верхняя панель

Слева направо:

1. **Иконка Object Builder.** Открывает небольшое меню «О программе», версия, документация и ссылка на репозиторий.
2. **Название Object Builder.** Не является кнопкой.
3. **Библиотека.** Возвращает к библиотеке. При несохранённых изменениях показывает диалог сохранения.
4. **Имя документа.** Показывает название открытого объекта. Нажатие позволяет переименовать его.
5. **Статус документа.** «Сохранено», «Есть изменения», «Сохранение…», «Ошибка сохранения». Нажатие на ошибку открывает подробности.
6. **Отменить.** Undo последнего действия. Disabled, если история пуста. Tooltip показывает название действия.
7. **Повторить.** Redo. Disabled, если повторять нечего.
8. **Попробовать.** Запускает Preview актуального черновика.
9. **Сохранить.** Сохраняет определение и сцену. Не сохраняет временное состояние Preview.
10. **Ещё.** Меню редких команд: Сохранить как, Дублировать, Создать шаблон, Проверить, Экспортировать, Открыть исходную сцену, Открыть документацию.
11. **Расширенные инструменты.** Переключает простой/расширенный режим, не меняя объект.
12. **Настройки.** Шестерёнка открывает настройки самого плагина.

В библиотеке панель вместо команд документа показывает «Создать объект», «Импортировать», фильтры, сортировку и вид карточек.

## 8. Навигация верхнего уровня

В простом режиме главные места:
- **Библиотека** — найти, открыть, создать и организовать объекты.
- **Конструктор** — редактировать выбранный объект.

Шаблоны — подраздел библиотеки. Диагностика открывается только по запросу или при наличии проблемы. Не создавать отдельные главные вкладки для здоровья, разрушения, звука и прочих механик.

# III. Библиотека объектов

## 9. Общая компоновка

Экран библиотеки состоит из:
- левой навигационной колонки;
- верхней панели поиска и действий;
- центральной области карточек или списка;
- правой панели сведений о выделенном объекте;
- необязательной строки статуса.

Библиотека должна быть похожа на удобный каталог, а не на файловую систему.

## 10. Левая колонка

### 10.1. Основные пункты

- **Все объекты** — сбрасывает фильтр категории и показывает всю библиотеку.
- **Избранное** — показывает объекты со звёздочкой.
- **Недавние** — показывает последние открытые/созданные объекты; по умолчанию до 20 записей.
- **Категории** — дерево пользовательских категорий.
- **Коллекции** — пользовательские подборки.
- **Шаблоны** — каталог заготовок.

У каждого пункта есть иконка, название и при необходимости счётчик. Повторный выбор активного пункта не перезагружает библиотеку без необходимости.

### 10.2. Стандартные категории

Стартовый набор:
- Природа: деревья, камни, растения, кусты.
- Постройки: дома, стены, крыши, заборы.
- Предметы: материалы, еда, ресурсы.
- Снаряжение: оружие, инструменты, броня.
- Мебель: столы, стулья, шкафы.
- Персонажи: игроки, NPC, враги.
- Животные: домашние, дикие.
- Интерактивные: двери, сундуки, механизмы.
- Эффекты: частицы, визуальные эффекты.
- Транспорт: лодки, телеги, машины.
- Пользовательские: созданные пользователем категории.

Это только навигация. Категория не разрешает и не запрещает объекту игровые возможности.

### 10.3. Строка категории

Содержит:
- стрелку раскрытия;
- иконку;
- название;
- число объектов;
- меню действий.

Меню:
- Открыть категорию.
- Создать объект в категории.
- Добавить подкатегорию.
- Переименовать.
- Выбрать иконку.
- Переместить выше/ниже.
- Удалить категорию.

Удаление категории не удаляет объекты. Сначала требуется выбрать, куда перенести её содержимое: в другую категорию или в «Без категории».

### 10.4. Коллекции

Кнопка «Создать коллекцию» открывает поля «Название», «Описание», «Иконка». Название обязательно.

Строка коллекции содержит название, количество записей и меню:
- Открыть.
- Добавить объекты.
- Переименовать.
- Изменить иконку.
- Удалить коллекцию.

Коллекция хранит ссылки на объекты, а не копии. Удаление коллекции не удаляет её содержимое из библиотеки.

**Реализованный срез 0.8.0-dev:** коллекция создаётся по названию, отображается отдельным режимом в фильтре библиотеки, сохраняется в метаданных проекта. Для выбранного объекта доступны «В коллекцию: …» и «Убрать из этой коллекции». Кнопка управления выбранной коллекцией позволяет переименовать или удалить её. Иконка, описание, счётчики и древовидная навигация пока не реализованы.

### 10.5. Недавние

Список сортируется по времени последнего открытия. Для каждой строки доступны «Открыть» и «Убрать из недавних». Недоступный файл не удаляется из библиотеки автоматически: запись помечается и предлагает «Найти файл» или «Убрать из истории».

## 11. Верхняя панель библиотеки

1. **Поиск.** Placeholder: «Найти объект…». В реализации 0.8.0-dev ищет по имени, описанию, ID, категории, типу, тегам, названиям и описаниям включённых возможностей, их ключевым словам, обязательным зависимостям и пользовательским свойствам. Крестик очищает поле. Расширенное поведение Enter/Esc и подсветка совпадений остаются целевыми улучшениями.
2. **Фильтры.** Открывает выдвижную панель. На кнопке показывается количество активных фильтров.
3. **Сортировка.** Меню: Имя A–Я, Имя Я–А, Недавно изменённые, Недавно созданные, Категория, Тип/назначение.
4. **Сетка.** Показывает карточки.
5. **Список.** Показывает табличные строки.
6. **Создать объект.** Главное действие.
7. **Импортировать.** Импорт сцены или пакета.
8. **Меню библиотеки.** Проверить библиотеку, обновить список, управление категориями, управление тегами, настройки отображения.

## 12. Панель фильтров

Элементы:
- Категория — дерево или выпадающий список.
- Теги — мультивыбор с поиском.
- Возможности — мультивыбор по понятным названиям.
- Статус — Все, Готовые, Есть предупреждения, Есть ошибки, Черновики, Отсутствуют ресурсы.
- Тип записи — Объект, Шаблон, Вариант, Импортированная сцена.
- Применить.
- Сбросить.

Под поиском показываются активные фильтры отдельными метками. Крестик удаляет только соответствующий фильтр. «Сбросить всё» отключает все фильтры разом.

## 13. Карточка объекта — режим сетки

Карточка включает:
1. Миниатюру: пользовательская, затем захваченная из Preview, затем placeholder.
2. Звёздочку избранного: переключает избранное без открытия объекта.
3. Название: до двух строк, затем сокращение.
4. Категорию.
5. Краткие метки возможностей, если помещаются.
6. Статус: готов, предупреждение, ошибка, нет ресурса.
7. Контекстное меню.

В реализации 0.8.0-dev левый клик по карточке выделяет и открывает объект; кнопка «Действия…» и ПКМ открывают меню действий. Двойной клик пока не является отдельной командой. Перетаскивание в игровую сцену и «Добавить в сцену» остаются целевыми функциями.

Контекстное меню:
- Открыть.
- Дублировать.
- Создать на основе.
- Создать шаблон.
- Добавить/убрать из избранного.
- Добавить в коллекцию.
- Изменить категорию.
- Переименовать.
- Экспортировать.
- Найти использование.
- Удалить.

**Реализовано в 0.8.0-dev:** Открыть, Создать копию, Создать шаблон из объекта, Переименовать, Удалить, Экспортировать .tres, Добавить в выбранную коллекцию и Убрать из текущей коллекции. Избранное переключается также из меню выбранной записи и применяется к объектам и шаблонам; пакетные операции, поиск использования и изменение категории из меню остаются в плане.

## 14. Карточка объекта — режим списка

Колонки:
- миниатюра;
- название;
- категория;
- основные возможности;
- дата изменения;
- состояние;
- избранное.

Нажатие на заголовок сортирует по колонке. Поддерживается выбор нескольких строк. Контекстное меню совпадает с меню карточки, но команды массового действия применяются ко всему выделению. Перед групповым удалением показать перечень объектов.

## 15. Правая панель сведений

По умолчанию компактная, скрываемая.

Поля:
- большая миниатюра;
- название;
- категория и теги;
- описание;
- статус проверки;
- список основных возможностей;
- версия определения;
- дата изменения;
- число зависимостей.

Кнопки:
- **Открыть** — открыть в Конструкторе.
- **Добавить в сцену** — создать экземпляр в активной сцене.
- **Дублировать** — создать независимую копию с новым ID.
- **Ещё** — экспорт, создать шаблон, переместить, найти использования, удалить.
- **Показать зависимости** — раскрыть используемые текстуры, аудио, сцены и расширения.

## 16. Пустые состояния библиотеки

- Пустая библиотека: «Здесь пока нет объектов» + «Создать объект» и «Импортировать».
- Нет результатов поиска: «Ничего не найдено» + «Очистить поиск».
- Нет избранного: объяснить значок звезды.
- Нет коллекций: предложить «Создать коллекцию».
- Пустая категория: «Создать объект в этой категории».
- Файл отсутствует: показать предупреждение и «Найти файл» / «Убрать запись».

# IV. Мастер создания

## 17. Общие правила

Мастер короткий. Он не задаёт технических вопросов, на которые плагин может ответить сам.

Каждый экран имеет:
- заголовок;
- краткое объяснение;
- область выбора;
- основную кнопку;
- «Назад»;
- «Отмена»;
- индикатор шага, если шагов больше одного.

## 18. Экран WIZ-01 — способ создания

Заголовок: «Как начнём?»

Карточки:
1. **С нуля** — создать пустую основу.
2. **Из шаблона** — взять готовую заготовку.
3. **Сделать копию** — повторно использовать объект как независимую копию.
4. **Импортировать сцену** — взять существующую сцену Godot.

Клик выбирает карточку, двойной клик может сразу продолжить. Кнопка «Продолжить» доступна после выбора.

## 19. Экран WIZ-02 — что примерно создаём

Карточки с иллюстрациями:
- Предмет.
- Ресурс.
- Оружие.
- Инструмент.
- Персонаж.
- NPC.
- Животное.
- Контейнер.
- Механизм.
- Постройка.
- Эффект.
- Другое.

Кнопка «Не знаю — обычный объект» пропускает профиль.

Подпись: «Это только стартовая подсказка. Позже можно добавить любые совместимые возможности». Выбор не задаёт закрытый тип объекта и не ограничивает каталог.

## 20. Экран WIZ-03 — имя и библиотека

Поля:
- Название объекта — обязательное.
- Категория — необязательная, по умолчанию предлагает категорию профиля.
- Теги — необязательные, с автодополнением.
- Описание — необязательное.
- Иконка — необязательная.
- Папка — автоматически, ручное изменение скрыто в дополнительных настройках.

Служебный ID создаётся автоматически и не показывается в простом режиме.

Кнопки:
- «Создать объект» — создать Definition и Scene, открыть Конструктор.
- «Назад».
- «Отмена».

Корневой класс Godot не запрашивается.

## 21. Копирование

Диалог содержит:
- карточку исходного объекта;
- новое имя;
- категорию;
- теги;
- переключатель «Копировать пользовательские настройки» (включён по умолчанию);
- «Создать копию»;
- «Отмена».

Копия получает новый ID. Исходник не меняется. Внутренние ссылки копии переназначаются безопасно; внешние ссылки не переписываются без решения пользователя.

## 22. Импорт сцены

Диалог:
- поле пути;
- «Обзор…»;
- результат анализа;
- список найденных частей;
- внешние ресурсы;
- пользовательские скрипты;
- предупреждения о неизвестном содержимом;
- кнопка «Импортировать копию»;
- «Отмена».

Оригинал не изменяется. Неизвестные узлы и скрипты сохраняются. Если импорт не может преобразовать часть содержимого в простой интерфейс, она остаётся в объекте и доступна в расширенном режиме.

## 23. Завершение мастера

После создания:
- открывается Конструктор;
- показывается уведомление «Объект создан»;
- открывается вкладка «Внешний вид»;
- черновик имеет статус «Есть изменения» или «Новый объект» до сохранения;
- пользователь видит пустую область с подсказкой «Добавьте изображение или часть».

# V. Конструктор — простой режим

## 24. Основная раскладка

Экран содержит четыре области:

1. Верхняя панель документа.
2. Левая панель с вкладками «Внешний вид», «Возможности», «Настройки».
3. Большое центральное визуальное поле.
4. Контекстная панель, которая появляется только при выборе части или команды «Настроить».

Нижняя техническая панель скрыта. Она появляется при проверке или если есть проблема, требующая внимания.

## 25. Левая панель

### Вкладка «Внешний вид»

Содержит:
- список частей объекта;
- «Добавить изображение»;
- «Добавить часть»;
- «Добавить анимацию»;
- пустое состояние, если частей нет.

Строка части:
- миниатюра;
- имя;
- тип;
- видимость;
- блокировка;
- ручка перетаскивания для порядка;
- меню действий.

Клик выделяет часть и показывает рамку на canvas. Двойной клик переименовывает. Перетаскивание меняет порядок отрисовки.

Меню части:
- Переименовать.
- Дублировать.
- Скрыть/показать.
- Заблокировать/разблокировать.
- Переместить выше.
- Переместить ниже.
- Удалить.

Удаление части с зависимостями показывает список ссылок и варианты действий. Все операции отменяемы.

### Вкладка «Возможности»

Показывает включённые возможности и кнопку «Добавить возможность».

Карточка возможности:
- иконка;
- обычное название;
- короткое описание;
- статус;
- переключатель Вкл/Выкл;
- кнопка «Настроить»;
- меню дополнительных действий.

Меню:
- Настроить.
- Временно отключить/включить.
- Удалить.
- Подробнее.
- Показать техническую реализацию (только расширенный режим).

Отключение сохраняет настройки. Удаление показывает, какие связанные данные останутся и что будет удалено.

### Вкладка «Настройки»

Показывает только свойства включённых возможностей и пользовательские свойства.

Верхняя часть:
- поиск по параметрам;
- фильтр «Основные / Все доступные»;
- «Добавить своё свойство»;
- «Сбросить настройки» с подтверждением.

Группы создаются автоматически и отображаются только если не пусты:
- Основное.
- Внешний вид.
- Взаимодействие.
- Движение.
- Здоровье и урон.
- Инвентарь и предметы.
- Разрушение и добыча.
- Звук и эффекты.
- Поведение.
- Пользовательские свойства.

Группа сворачивается/разворачивается. Положение групп сохраняется как настройка интерфейса и не меняет данные объекта.

## 26. Кнопки и инструменты центрального поля

Мини-панель canvas:
1. **Выбор** — выбрать часть объекта.
2. **Перемещение** — переместить выделенное мышью.
3. **Поворот** — вращать выделенное.
4. **Масштаб** — изменить размер.
5. **По размеру объекта** — центрировать и выбрать подходящий масштаб.
6. **Сетка** — включить/выключить направляющие.
7. **Привязка** — включить/выключить snap.
8. **Фон** — прозрачная шахматка, светлый или тёмный фон.
9. **Сбросить вид** — вернуть масштаб и позицию камеры поля.
10. **Вспомогательные элементы** — показать рамки, pivot и метки.

Не показывать инструмент, если он не применим к текущему выделению.

Управление:
- левый клик — выделение;
- перетаскивание — действие активного инструмента;
- колёсико — zoom;
- средняя кнопка мыши — pan;
- правый клик — контекстное меню;
- Esc — отменить текущий инструмент/закрыть меню.

Все сочетания настраиваются.

## 27. Добавление изображения и частей

### Кнопка «Добавить изображение»
Открывает единый выбор ресурса:
- поиск;
- «В проекте»;
- «Файловая система»;
- сетка миниатюр/список;
- Preview выбранной текстуры;
- «Выбрать»;
- «Импортировать»;
- «Отмена».

### Кнопка «Добавить часть»
Меню:
- Изображение.
- Часть из спрайтшита.
- Анимированная часть.
- Визуальный эффект (при наличии расширения).
- Группа частей.
- Часть из существующего объекта.

Каждый пункт имеет короткое объяснение. Неподдерживаемые пункты не показываются как доступные команды.

## 28. Контекстная панель визуальной части

Если выбрана часть изображения, показать:
- имя;
- заменить изображение;
- размер;
- позиция;
- поворот;
- отражение по горизонтали;
- отражение по вертикали;
- прозрачность;
- дополнительные настройки;
- дублировать;
- удалить.

Дополнительные параметры:
- область текстуры;
- HFrames/VFrames;
- номер кадра;
- смещение;
- центрирование;
- фильтрация;
- Z-порядок;
- точный pivot.

Кнопка «Сбросить трансформацию» возвращает исходные положение, поворот и размер только выбранной части.

## 29. Редактор спрайтшита

Элементы:
- Колонки.
- Строки.
- Сетка кадров.
- Выбранный кадр.
- Автоподбор сетки.
- Предпросмотр выделенной ячейки.
- Прямоугольное выделение произвольного фрагмента.
- «Применить».
- «Отмена».

Автоподбор предлагает вариант и не применяет его без подтверждения. Если ячейки разного размера, пользователь может выделить область вручную. Прозрачные поля не обрезаются самопроизвольно.

## 30. Редактор анимации

Список анимаций содержит:
- имя;
- число кадров;
- скорость;
- Loop;
- статус проигрывания.

Кнопки:
- Добавить анимацию.
- Переименовать.
- Дублировать.
- Удалить.
- Воспроизвести.
- Пауза.
- Предыдущий кадр.
- Следующий кадр.

Поля:
- скорость;
- зацикливание;
- направление;
- стартовый кадр;
- число кадров;
- длительность кадра.

Если список пуст, показать «Создать анимацию» и «Назначить готовый ресурс».

## 31. Выбор части и контекстное меню canvas

Клик по части выделяет её. Выделение синхронизируется со списком частей. Если часть заблокирована, её можно выделить, но трансформировать нельзя до разблокировки.

Контекстное меню:
- Выбрать часть.
- Дублировать.
- Скрыть/показать.
- Заблокировать/разблокировать.
- Переместить вперёд/назад.
- Открыть настройки.
- Удалить.

Если под курсором несколько частей, показывается короткий список перекрывающихся элементов для точного выбора.

## 32. Контекстная панель возможности

При нажатии «Настроить»:
- заголовок и иконка возможности;
- короткое описание;
- включена/выключена;
- основные параметры;
- «Дополнительные настройки»;
- список обязательных зависимостей;
- «Отключить»;
- «Удалить»;
- «Подробнее».

Если ни одна часть и возможность не выбраны, панель закрыта. Пустой инспектор не отображается.

# VII. Настройки объекта и пользовательские свойства

## 40. Общий экран настроек

Вверху:
- заголовок «Настройки»;
- поиск параметров;
- фильтр «Основные / Все доступные»;
- «Добавить своё свойство»;
- «Сбросить настройки» с подтверждением.

Отображаются только настройки реально добавленных возможностей и пользовательские свойства.

## 41. Группы параметров

Автоматически формировать группы:
- Основное.
- Внешний вид.
- Взаимодействие.
- Движение.
- Здоровье и урон.
- Инвентарь и предметы.
- Разрушение и добыча.
- Звук и эффекты.
- Поведение.
- Пользовательские свойства.

Пустые группы не отображаются. Группы сворачиваются/разворачиваются. Их порядок является пользовательской настройкой интерфейса и не меняет структуру данных.

## 42. Типы полей и элементы управления

| Тип | Вид UI | Дополнительные команды |
|---|---|---|
| Boolean | переключатель + текстовое состояние | подсказка |
| Integer | числовое поле + стрелки | min/max, единица |
| Float | ползунок + точное число | min/max/step |
| String | строковое поле | очистить |
| Text | многострочное поле | развернуть редактор |
| Enum | выпадающий список | поиск, описание варианта |
| Color | цветной образец | открыть палитру |
| Vector2 | X и Y | сброс |
| Vector3 | X/Y/Z в расширенном режиме | сброс |
| Texture | миниатюра + «Выбрать» | заменить/очистить |
| AudioStream | имя + «Выбрать» + Play/Stop | заменить/очистить |
| PackedScene/объект | карточка ресурса | выбрать/открыть |
| Array | список значений | добавить/изменить/удалить/переставить |
| Dictionary | таблица ключ/значение в расширенном режиме | добавить/удалить строку |

Число можно ввести вручную, даже если доступен ползунок. Единицы измерения должны быть подписаны.

## 43. Строка настройки

Каждая строка содержит:
- понятную подпись;
- значение;
- единицу измерения;
- подсказку;
- пометку «Дополнительно», если нужно;
- меню действий, когда оно применимо.

Меню:
- Сбросить к значению по умолчанию.
- Копировать значение.
- Вставить значение.
- Открыть определение (расширенный режим).

При изменении поле регистрирует Undo/Redo, помечает объект изменённым и обновляет Preview, если это безопасно.

## 44. Условия показа полей

Настройки зависят от выбранных возможностей. Например, время автозакрытия показывается, только если включено «Автоматически закрывать». При скрытии поле не удаляется: прежнее значение сохраняется.

## 45. Добавить собственное свойство

Диалог в простом режиме:
- Название — обязательно.
- Тип — выбор из понятных типов.
- Значение по умолчанию.
- Описание — необязательно.
- Группа.
- Диапазон для чисел.
- Уровень: Основное/Дополнительное.
- Кнопки «Добавить» и «Отмена».

Внутренний property_id генерируется автоматически и скрыт.

В расширенном редакторе доступны ID, сериализация, условия видимости, группы, единицы измерения, Enum options, редактируемость, включение в шаблон и поиск использований.

## 46. Сброс настроек

Кнопка «Сбросить настройки» должна перечислить, что сбрасывается: параметры возможностей, пользовательские значения или оба набора. По умолчанию не трогать внешний вид, ресурсы и структуру сцены. Предусмотреть «Сбросить всё» только внутри подтверждаемого расширенного диалога.

# VIII. Предпросмотр (Preview)

## 47. Открытие Preview

Кнопка «Попробовать» открывает Preview актуального черновика, даже если он ещё не сохранён. Preview не использует устаревшую версию объекта из библиотеки.

## 48. Верхняя панель Preview

Уже реализованные кнопки/поля:
- **− / +** — уменьшить или увеличить масштаб области просмотра.
- **Масштаб (%)** — показывает текущий масштаб.
- **Вписать** — автоматически подобрать масштаб и положение камеры, чтобы видимая часть объекта целиком помещалась в окне.
- **Центр** — вернуть камеру к началу координат объекта.
- **Сбросить** — пересоздать чистую копию из актуального черновика; временное состояние предыдущей копии удаляется.
- Закрытие окна останавливает Preview и освобождает временный экземпляр.

Запланированные элементы:
- **Запустить** — старт тестового экземпляра с разрешённой игровой логикой.
- **Пауза / Продолжить** — управлять симуляцией.
- **Скорость** — 0.5×, 1×, 2×, если поддерживается.
- **Остановить** — выйти в редактор.

Запустить, Пауза и Продолжить взаимоисключающие состояния.

## 49. Переключатели отображения

- Показать коллизии.
- Показать области взаимодействия.
- Показать hitbox/hurtbox.
- Показать точки крепления.
- Показать направления/траектории.
- Показать отладочную информацию.

По умолчанию служебные слои выключены.

## 50. Тестовые действия

Показывать только применимые к выбранным возможностям:
- Взаимодействовать.
- Нанести тестовый урон.
- Восстановить здоровье.
- Подобрать.
- Открыть/закрыть.
- Создать тестовый предмет.
- Сбросить состояние.

Тестовые действия изменяют только временный экземпляр.

## 51. Итог Preview

Сводка:
- что успешно проверено;
- что не удалось проверить;
- найденные ошибки и предупреждения;
- «Вернуться к проблеме»;
- «Повторить»;
- «Закрыть».

Нельзя писать «Полностью проверено», если Preview не поддерживает часть механик. Preview не создаёт демонстрационные .tscn-сцены и не сохраняет тестовое состояние в библиотеку.

# IX. Диагностика

## 52. Как открыть

Диагностика открывается:
- по кнопке «Проверить» в меню «Ещё»;
- из уведомления об ошибке;
- по команде «Проверить библиотеку».

Не держать большую панель ошибок постоянно открытой.

## 53. Разделы диагностики

- **Ошибки** — препятствуют работе или сохранению.
- **Предупреждения** — объект может работать, но есть риск.
- **Информация** — сведения о формате и необязательные рекомендации.
- **Зависимости** — сцены, текстуры, аудио, компоненты, пакеты.
- **История** — проверки и миграции.

## 54. Карточка проблемы

Содержит:
- уровень важности;
- короткое название;
- человеческое объяснение;
- имя объекта и затронутой части;
- кнопку «Исправить» или «Перейти»;
- «Подробнее» с техническими данными.

Если исправление автоматическое, сначала описать план. Ошибки не должны показывать новичку только NodePath или traceback.

## 55. Статусы объекта

- **Готов** — критических проблем нет.
- **Есть предупреждения** — объект можно использовать, но рекомендуется проверить.
- **Нужно исправить** — критическая проблема.
- **Не проверен** — после последних изменений проверка не выполнялась.
- **Нужен пакет** — отсутствует расширение.

Иконка всегда сопровождается текстом и tooltip.

# XIII. Расширенный режим

## 64. Общий принцип

Расширенный режим — другой вид тех же данных, а не отдельная система и не копия объекта.

## 65. Левая панель

Вкладки:
- **Сцена** — фактическое дерево Godot.
- **Компоненты** — внутренние привязки возможностей к узлам.
- **Связи** — ссылки, sockets, зависимости между частями.
- **Свойства** — полная схема пользовательских полей.

## 66. Дерево сцены

Верхняя строка:
- поиск узла;
- «Добавить узел»;
- «Добавить группу»;
- раскрыть всё;
- свернуть всё;
- фильтр скрытых/служебных элементов.

Строка узла:
- стрелка раскрытия;
- иконка типа;
- имя;
- видимость;
- индикатор проблемы;
- индикатор назначенных компонентов.

Контекстное меню:
- Выделить.
- Переименовать.
- Добавить дочерний узел.
- Дублировать.
- Переместить.
- Удалить.
- Открыть штатный Inspector.
- Открыть скрипт.
- Показать зависимости.

Корень нельзя удалить. Если на узел есть ссылки, перед удалением показать их и варианты переназначения.

## 67. Добавление узла

Диалог:
- поиск по имени/назначению;
- категории узлов;
- список типов;
- короткое описание;
- «Добавить»;
- «Отмена».

Рекомендуемые узлы располагаются сверху. Все допустимые поддерживаемые типы доступны через поиск. В простом режиме этот диалог скрыт.

## 68. Список привязок компонентов

Строка:
- название типа;
- целевой узел;
- включено/выключено;
- совместимость;
- меню.

Команды:
- Добавить компонент.
- Настроить.
- Выбрать другой узел.
- Дублировать привязку, если тип допускает.
- Отключить/включить.
- Удалить.

Компонентная привязка — внутренняя запись. Она не обязана быть дочерним узлом SceneTree. Явно заданный отсутствующий target приводит к ошибке, а не к скрытому переносу на корень.

## 69. Таблица пользовательских свойств

Колонки:
- отображаемое имя;
- внутренний ID;
- тип;
- группа;
- уровень;
- значение по умолчанию;
- использование.

Кнопки:
- Добавить.
- Редактировать.
- Дублировать как новое свойство.
- Удалить.
- Найти ссылки.

Дублирование создаёт новый ID. Удаление используемого свойства требует разрешить ссылки.

## 70. Центральное поле расширенного режима

То же поле, что и в простом режиме, с дополнительными слоями:
- дерево/узлы;
- pivot/origin;
- sockets;
- коллизии;
- hitbox/hurtbox;
- физические области;
- точки появления;
- области действия;
- траектории.

Каждый слой включается отдельно. Клик по визуальной области выделяет её в дереве. Выбор узла в дереве подсвечивает его в поле.

## 71. Правая панель Inspector

Вкладки:
- **Объект** — ID, имя, категория, теги, описание, версия, зависимости.
- **Узел** — штатные свойства Godot.
- **Компонент** — тип, ID привязки, target, enabled, версия, settings, зависимости.
- **Связи** — object links, sockets и целевые узлы.

Стандартные поля Godot редактируются штатным Inspector или его официально расширяемой интеграцией. Не создавать второй независимый редактор тех же значений.

## 72. Нижняя панель

Вкладки:
- Ошибки.
- Предупреждения.
- Ресурсы.
- Зависимости.
- События.
- Лог Preview.
- История изменений/миграций.

По умолчанию свернута. Может появиться при критической ошибке, но не должна перекрывать центральное поле без необходимости.

## 73. Состояния и события

Список состояний:
- имя;
- стартовое состояние;
- количество переходов;
- добавить;
- дублировать;
- удалить.

Состояние может задавать видимость, текстуры, анимации, коллизии, действия, свойства, звук и эффекты.

Редактор событий:
- список событий;
- источник события;
- условия;
- действия;
- переход к следующему состоянию;
- порядок выполнения;
- обработка ошибки.

Схема: событие → условие → действие → переход. Каждый блок имеет подпись, описание, настройки, входы/выходы и индикатор совместимости. Проверка недостижимых блоков и некорректных циклов выполняется диагностикой.

# XV. Безопасность и управление данными

## 83. Удаление объекта

Диалог показывает:
- имя и миниатюру;
- другие объекты, которые на него ссылаются;
- размещённые экземпляры, если их можно найти;
- принадлежащие ему зависимости;
- что именно будет удалено.

Кнопки:
- «Удалить объект».
- «Отмена».
- «Подробнее о зависимостях».

При активных ссылках нельзя молча удалять используемые файлы. Предложить сначала заменить ссылки или отвязать объект.

## 84. Переименование и ID

Обычное переименование меняет отображаемое имя, не постоянный ID. Изменение ID доступно только в расширенном режиме как отдельная операция с предварительной проверкой ссылок, backup и подтверждением.

## 85. Обновление экземпляров

При изменении исходного Definition:
- показать базовую и новую версии;
- список изменённых полей и возможностей;
- конфликтующие overrides;
- выбор экземпляров для обновления;
- возможность оставить экземпляр без изменений или отвязать;
- backup перед операцией.

Не обновлять все экземпляры автоматически.

## 86. Undo/Redo

Любое изменение структуры, части, свойства или возможности регистрируется в общей истории, если операция поддерживается. Добавление возможности со всеми обязательными зависимостями — одна отменяемая операция.

Названия операций понятные: «Добавлена возможность “Можно подобрать”», «Изменено изображение», «Добавлена коллизия». Не показывать новичку список низкоуровневых методов.

# XVI. Состояния и ошибки интерфейса

## 87. Состояния любого экрана/списка

Нужно предусмотреть:
- загрузка;
- данные загружены;
- пусто;
- поиск не дал результатов;
- фильтр не дал результатов;
- ошибка загрузки;
- ресурс недоступен;
- нет прав на запись;
- выполняется операция.

Нельзя оставлять пустую белую панель без пояснения и следующего действия.

## 88. Состояния документа

- Новый черновик.
- Сохранён.
- Несохранённые изменения.
- Сохраняется.
- Ошибка сохранения.
- Критическая ошибка.
- Предупреждения.
- Только чтение.
- Нужна миграция.
- Нужен пакет расширения.

У каждого статуса есть текст, иконка и tooltip. Цвет только дополняет сообщение.

## 89. Состояния кнопок

- Обычная.
- Hover.
- Фокус клавиатуры.
- Нажата.
- Недоступна.
- Выполняется операция.

При загрузке нельзя допустить повторного запуска той же операции. Нельзя показывать «Готово», пока результат действия не подтверждён.

## 90. Уведомления

Примеры:
- Успех: «Объект сохранён».
- Информация: «Предпросмотр сброшен».
- Предупреждение: «У объекта есть непроверенная возможность».
- Ошибка: «Не удалось сохранить. Проверьте доступ к папке».

Некритичные уведомления не блокируют работу. Критические остаются в диагностике. Уведомление может содержать одну основную кнопку действия.

## 91. Когда нужно подтверждение

Обязательное подтверждение:
- удаление объекта;
- удаление части с зависимостями;
- удаление свойства, используемого логикой;
- изменение постоянного ID;
- массовое обновление;
- импорт с конфликтами;
- очистка backup;
- удаление/отключение используемого расширения.

Не требовать подтверждения для обычного перемещения, масштаба, поворота, скрытия, простого изменения параметра или добавления безопасной части, если действие можно отменить.

# XVII. Адаптация, локализация, доступность

## 92. Узкое окно

При обычной ширине видны левая панель, canvas и контекстная панель.

При узкой ширине:
- контекстная панель превращается в выдвижную область;
- список частей можно свернуть;
- важные кнопки сохраняют подписи;
- не заменять все команды одними иконками.

Минимальная ширина должна сохранять доступ к основным действиям.

## 93. Сохранение раскладки

Сохранять:
- ширину панелей;
- свёрнутые области;
- состояние контекстной панели;
- активную вкладку конструктора;
- масштаб и положение canvas;
- простой/расширенный режим.

Кнопки: «Сбросить раскладку», «Сохранить рабочее пространство» (будущая возможность), «Переключить рабочее пространство».

## 94. Доступность

- клавиатурная навигация по карточкам и спискам;
- заметный фокус;
- подписи, доступные screen reader там, где это поддерживает Godot;
- иконки не являются единственным обозначением команды;
- масштаб не обрезает текст;
- основные действия имеют достаточную область нажатия.

## 95. Локализация

Все строки UI хранятся в системе локализации, а не зашиваются в коде экранов. Технические ID и названия классов скрыты в простом режиме и не переводятся. Пользовательские подписи и описания должны поддерживать перевод по мере развития системы.

# XIX. Критерии приёмки и порядок реализации

## 98. Проверка новичком

Человек, который не знает Godot, должен суметь:
1. открыть библиотеку;
2. создать обычный объект;
3. добавить изображение;
4. добавить ещё одну часть;
5. выбрать одну-две возможности;
6. изменить понятный параметр;
7. попробовать объект;
8. сохранить его;
9. добавить экземпляр в игровую сцену.

Не допускается требовать выбора корневого класса Godot, ручного SceneTree, Component Binding, NodePath, сигналов или GDScript.

## 99. Проверка универсальности

Одинаковый путь должен работать для:
- подбираемого предмета;
- ресурса;
- оружия или снаряда;
- персонажа/NPC;
- интерактивного механизма;
- составного объекта.

Не должно быть отдельных режимов «дерево», «сундук», «оружие». Профиль только предлагает начало.

## 100. Проверка расширенного режима

Опытный пользователь должен уметь:
- открыть SceneTree;
- добавить поддерживаемый узел;
- назначить компонент конкретному узлу;
- редактировать свойства и связи;
- работать с коллизиями и sockets;
- открыть штатный Inspector;
- использовать GDScript;
- вернуться в простой режим без потери данных.

## 101. Проверка безопасности

Проверить Undo/Redo, удаление зависимой части, отключение и удаление возможности, конфликт ID, потерю ресурса, ошибку сохранения, backup/restore, обновление экземпляров с overrides и отключённое расширение.

Автоматические проверки runtime выполняются smoke-тестами. Не создавать отдельные демонстрационные .tscn-сцены только для проверки математики или простых API.

## 102. Приоритет экранов

Первый пользовательский вертикальный срез:
1. LIB-01 — библиотека.
2. WIZ-01…WIZ-03 — короткий мастер.
3. EDIT-01 — внешний вид.
4. EDIT-02 — возможности.
5. EDIT-03 — настройки.
6. PRE-01 — Preview простого объекта.
7. Сохранение и добавление в сцену.

Следующий слой:
8. Фильтры, категории, теги и коллекции.
9. Полный каталог возможностей и зависимости.
10. Диагностика с исправлениями.
11. Шаблоны, импорт и экспорт.
12. Расширенный режим SceneTree/Inspector.
13. Пользовательские свойства и связи.
14. Состояния и визуальные события.
15. Обновление экземпляров, расширения и миграции.

Не начинать с полного экспертного редактора, оставляя новичка без простого рабочего пути. Но формат данных с самого начала должен поддерживать версии, постоянные ID и расширяемость.

## 103. Финальный критерий

Object Builder — не панель с сотней настроек и не урезанный редактор Godot.

Это понятный визуальный конструктор игровых объектов. Пользователь выбирает результат, который хочет получить, а система занимается технической сборкой. Когда нужен полный контроль, пользователь открывает внутреннее устройство.

**Сложность — внутри. Простота — снаружи.**
