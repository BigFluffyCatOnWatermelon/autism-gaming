# Инструкции для AI-ассистента

Перед работой прочитай:
- `README.md`
- `PROJECT_STATE.md`
- `TASKS.md`
- последние записи `CHANGELOG.md`

Затем проверь реальные исходники и актуальную ветку. Документация может отставать от кода.

## Общие правила
- GitHub — основной источник истины; не полагайся на память прошлого чата.
- Стек: Phaser 4 + JavaScript + Vite; разработка через StackBlitz.
- Делай минимальные, законченные изменения; не переписывай несвязанные системы.
- Не удаляй существующие механики без прямой просьбы пользователя.
- Комментируй сложную логику и публичные API, чтобы новый чат мог продолжить разработку.
- Не придумывай за пользователя сюжет, жанр и художественные решения.
- Честно сообщай, что проверено, а что нет.

## Конфигурация
- Часто изменяемые параметры хранятся в `src/config/gameConfig.js`.
- Разделяй параметры по системам и снабжай их понятными комментариями.
- Поля для F3 объявляй в `DEBUG_FIELDS`: label, description, type, min/max/step или options.
- Не дублируй одно и то же значение в коде и конфиге.

## Игровые объекты
- Мир, игрок, предметы, ресурсы, враги и NPC должны использовать общие системы.
- Новый объект, который требуется редактировать через F3, регистрируй через `WorldScene.registerDebugTarget()`.
- Для объектных полей используй `fields` с `getValue` и `setValue`.
- Боевые цели регистрируй через `WorldScene.registerCombatTarget()`.
- Используй общую систему материалов и типов урона из `CombatSystem.js`, не создавай параллельные формулы.

## Графика и лицензии
- Игровые ассеты хранятся в `public/assets/`.
- Для каждого стороннего набора записывай автора, исходную ссылку и лицензию в `public/assets/ASSET_SOURCES.md`.
- Не добавляй платные или нелицензированные ресурсы.
- Сохраняй пиксельный стиль и nearest-neighbor масштабирование.

## Проверка и документация
- После изменений логики выполняй `npm test`.
- Проверяй `npm run build` через GitHub Actions.
- По возможности проверяй изменённую механику в StackBlitz.
- После каждой завершённой задачи обновляй `PROJECT_STATE.md`, `TASKS.md` и `CHANGELOG.md`.
- Незавершённые задачи не отмечай выполненными.
