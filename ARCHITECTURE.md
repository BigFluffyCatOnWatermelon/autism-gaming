# Архитектура Object Builder

## Главный принцип

Редакторский плагин, библиотека определений и runtime-исполнение — три независимых слоя. Выключение Object Builder не должно ломать игру или загрузку уже созданных объектов.

## Слои

### 1. Object Builder — editor-only

Путь: addons/object_builder/

Задачи плагина: навигация по категориям, поиск, формы метаданных, редактор пользовательских свойств, запуск стандартного редактора сцен. Плагин не содержит боевую логику и не управляет игровыми экземплярами.

Интерфейс остаётся компактным: слева поиск, переключение Все/Избранное/Недавние, категория, тег и список объектов; справа свойства выбранного объекта и сгруппированные области. Избранное и недавние ID хранятся через EditorSettings project metadata вне папки проекта, поэтому пользовательские предпочтения не попадают в Git.

Плагин показывает дерево только если в редакторе открыта сцена, чей scene_file_path совпадает со scene_path выбранного определения. Это защищает от случайного изменения другой сцены. Добавление и удаление узлов регистрируются в EditorUndoRedoManager и входят в общую историю Ctrl+Z/Ctrl+Y. Сохранение сцены остаётся обычным действием редактора (Ctrl+S).

Для выбранного Sprite2D доступна компактная визуальная панель: предпросмотр Texture2D, выбор текстуры из res://, HFrames/VFrames, Frame, Offset X/Y, Centered и Flip H/V. Для AnimatedSprite2D можно назначить SpriteFrames, выбрать анимацию и кадр, просматривать выбранный кадр и менять Speed Scale (в том числе отрицательный для обратного направления). Автовоспроизведение задаётся через Autoplay в штатном Inspector; в панели пока нет кнопок Play/Pause и настройки Loop Mode. Все изменения узлов применяются через EditorUndoRedoManager, штатный Inspector остаётся доступен для остальных свойств. Собственного collision editor пока нет.

### 2. Object System — runtime

Путь: scripts/object_system/

- ObjectDefinition — Resource-описание объекта и версия схемы.
- ObjectPropertyDefinition — ID, отображаемое имя, тип, значение по умолчанию, группа и описание пользовательского свойства.
- ObjectPropertyData — дочерний узел сцены с сериализуемыми определениями/значениями и динамическими типизированными полями Inspector.
- ObjectComponentDefinition — подключаемый компонент, категория, версия, скрипт, схема типизированных настроек и сериализуемые значения.
- ObjectComponentCatalog — каталог категорий и встроенных компонентов; сейчас доступны Health, Damageable и Attack.
- ObjectComponent — базовый Node-контракт с постоянным component_id и настройками.
- HealthComponent — здоровье, урон, лечение, смерть, неуязвимость и сброс состояния.
- DamageableComponent — фильтрует входящий урон, применяет множитель/плоское снижение и передаёт итог в Health.
- AttackComponent — наносит урон цели с Damageable, проверяет дальность и cooldown; итоговый урон модифицируется на стороне цели.
- ComponentTestScene — изолированная сцена-песочница для Health/Damageable; создаёт тестовый объект через ObjectFactory и не меняет основную игровую сцену.
- ObjectFactory — создание экземпляра, разрешение компонентов по ID, применение настроек и поиск компонента.
- ObjectRegistry — поиск определений и создание объектов по постоянному ID.

Runtime не зависит от EditorPlugin и может использоваться при выключенном плагине.

### 3. Object Library — данные

Путь: data/object_library/

- objects/<id>.tres — определения объектов.
- templates/<id>.tres — шаблоны.
- scenes/<id>.tscn — сцены объектов.
- Категория и теги хранятся внутри определения; список пользовательских категорий не зашит в формат файла.

## Идентичность и данные

Постоянный object_id — ключ для ссылок и будущих сохранений. Отображаемое название, категория, описание и теги можно менять. Пользовательское свойство имеет собственный property_id; подпись в UI не используется как ключ.

Пользовательские свойства сохраняют типизированные значения String, Integer, Float, Boolean и Vector2. Для каждого свойства доступны постоянный property_id, отображаемая подпись, значение по умолчанию, группа, описание и флаг advanced. Для Integer/Float можно задать minimum/maximum; ObjectLibraryService проверяет целочисленные границы, порядок значений и попадание default в диапазон перед сохранением определения. Редактор изменяет описание свойства, не меняя его property_id. Флаг advanced пока отображается в списке свойств как пометка; отдельный режим скрытых настроек ещё предстоит реализовать.

ObjectFactory хранит пользовательские значения и определения в дочернем узле `ObjectProperties` (ObjectPropertyData). Его динамические свойства показываются в штатном Inspector как поля String, Integer, Float, Boolean и Vector2; группы и числовые min/max берутся из ObjectPropertyDefinition. Скрытые export-storage поля хранят схему и значения, а сами значения доступны через обычные динамические свойства. Поэтому изменения Inspector сохраняются вместе с `.tscn`; `ObjectFactory.get_custom_property()` и `set_custom_property()` читают/меняют тот же узел. Для совместимости Factory также обновляет прежние metadata-ключи. Интеграция с savegame пока не реализована.

## Компоненты

Компонент описывается через ObjectComponentDefinition и реализуется скриптом, наследующим ObjectComponent. Компонент получает настройки через configure(Dictionary); постоянный `component_id` позволяет найти экземпляр через `ObjectFactory.get_component()`.

ObjectComponentCatalog содержит категории Appearance, Physics, Stats, Combat, Interaction, Destruction, Audio и Procedural. Встроены `health` (HealthComponent, Stats), `damageable` (DamageableComponent, Combat), `attack` (AttackComponent, Combat) и `destructible` (DestructibleComponent, Destruction); остальные компоненты добавляются по мере появления реальных игровых сценариев. Каталог создаёт ObjectComponentDefinition с defaults и схемой настроек. Словарь `settings` переопределяет ключи каталога, а runtime-фабрика передаёт объединённые значения компоненту.

`ObjectComponentDefinition` предоставляет динамические типизированные поля штатного Inspector из схемы `setting_definitions`: String, Integer, Float, Boolean и Vector2, группы и числовые диапазоны. Значения сохраняются в `settings` как storage-only dictionary, чтобы не показывать дублирующий сырой словарь в Inspector. `set_setting()` проверяет типы и ограничивает числовые поля заданным диапазоном.

В Object Builder раздел «Компоненты» позволяет выбрать категорию и компонент, добавить его в определение, включить/отключить или удалить. Кнопка Inspector открывает ресурс ObjectComponentDefinition для правки полей; после изменения нужно сохранить определение через «Сохранить в библиотеку». Компоненты создаются ObjectFactory во время runtime-инстанцирования, а не становятся дочерними узлами сохраняемой `.tscn`.

HealthComponent предоставляет `apply_damage()`, `heal()`, `set_current_health()`, `set_max_health()`, `reset_health()`, `is_alive()` и `get_health_ratio()`, а также сигналы `health_changed`, `damaged`, `healed` и `died`. DamageableComponent предоставляет `receive_damage()`: вычисляет `max(0, incoming * multiplier - flat_reduction)`, передаёт итог в Health и излучает `damage_received` или `damage_blocked`. AttackComponent предоставляет `perform_attack(target, source)`: проверяет cooldown, дальность и наличие Damageable на цели, затем передаёт ей урон. Attack не управляет анимациями или выбором цели — это ответственность игрового контроллера. DestructibleComponent подписывается на `Health.died` и предоставляет `destroy(source)`, `repair()` и `is_destroyed()`. При разрушении он может отключить collision layer/mask и дочерние CollisionShape2D/CollisionPolygon2D, заблокировать Damageable, скрыть или удалить объект по настройке, записывает `object_destroyed` и выдаёт `destroyed(source)`. По умолчанию объект остаётся в сцене: его падение, пень, эффекты и дроп реализуются специализированной сценой/другими компонентами. `repair()` восстанавливает исходные коллизии, видимость, приём урона и, по настройке, стартовое здоровье. Компоненты пока не подключены к существующему игроку, ResourceNode или Debug Inspector.

Следующие компоненты по плану: DropTable, Harvestable, Interactable и Pickup. Затем — Audio, Particles и поведенческие компоненты.

## Определение, шаблон и экземпляр

Общее определение хранится в библиотеке; шаблон хранится отдельно и используется для создания независимой копии. Размещённый в сцене объект или созданный в игре узел — экземпляр. Изменение экземпляра не должно молча менять исходное определение.

Для дальнейшего развития нужны overrides, связь с версией определения, команды «обновить выбранные экземпляры», «отвязать» и предварительный просмотр изменений.

## Версии и восстановление

- Версия схемы данных отделена от версии плагина.
- Новая версия плагина должна читать старые определения либо предоставлять явную миграцию.
- Перед изменением существующего определения создаётся резервная копия .bak.
- Неизвестные поля и компоненты сохраняются; неизвестный скрипт компонента пропускается с предупреждением, а не удаляет данные.
- Автоматическое преобразование игровых ResourceNode и Cozy Village сцен запрещено без отдельной проверки и копии.

## Границы 0.1.0

Сейчас реализованы мастер типов, библиотека, дерево сцены, панели Sprite2D/AnimatedSprite2D, типизированные пользовательские свойства, каталог Health/Damageable/Attack и изолированная тестовая сцена компонентов. Шаблоны пока не поддерживают общее наследование и синхронизацию вариантов. Следующие крупные этапы — остальные компоненты, интеграция Attack с боевой системой и безопасная интеграция с игровыми объектами.
