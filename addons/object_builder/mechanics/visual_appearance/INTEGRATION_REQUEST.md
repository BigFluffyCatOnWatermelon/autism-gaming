# Интеграция: visual_appearance

Пакет содержит десять самостоятельных компонентов для Sprite2D, CanvasItem, Node2D, Control, Texture2D, Image и ShaderMaterial. Компоненты не зависят от конкретной игровой сцены.

## Уже подключено к ObjectFactory

1. ObjectFactory вызывает публичный `bind_target(Node)` после конфигурации и перед добавлением компонента в дерево.
2. Общая база находит Sprite2D/CanvasItem внутри назначенной ветки; каждый компонент применяет свои настройки к найденному целевому узлу.
3. `has_multiple_visual_parts` разрешает NodePath относительно переданного корня, не выходя за границы объекта.
4. Изменение настроек повторно применяет визуальный эффект к привязанной цели.
5. Временная тень создаётся дочерним Sprite2D источника и удаляется вместе с компонентом; обводка возвращает предыдущий Material; визуальные части восстанавливают позицию и видимость.
6. Palette swap каждый раз создаёт результат из исходной текстуры, а не из уже изменённой копии.
7. Object System smoke проверяет сборку экземпляра со всеми десятью visual_appearance компонентами и применение оттенка/прозрачности.

## Оставшиеся ограничения

- Ручная GUI-приёмка на разных типах целевых узлов и разрешениях Godot.
- Полный цикл Undo/Redo для runtime-эффектов в редакторском предпросмотре.
- Проверка восстановления исходных значений tint/opacity/flip/z-order при удалении каждого соответствующего компонента.
- Для palette swap исходная текстура фиксируется при первой привязке; замена внешней текстуры после привязки требует явного повторного bind_target().
- Тень следует за локальным transform Sprite2D, но не реализует отдельную систему проекции/контакта с поверхностью.

Не переводить карточки в `ready` только на основании target binding: нужны проверки каждого поведения, сериализации, Undo/Redo и ручная GUI-приёмка.
