# Integration request — interaction

## Что реализовано локально

- `can_interact`: проверяет готовность объекта и отправляет `interaction_requested`.
- `can_be_picked_up`: отправляет запрос подбора, ожидает `confirm_pickup(accepted)` и защищает от повторного запроса.
- `can_be_activated`: переключает общее состояние активности через metadata целевого узла.
- `can_be_opened` / `can_be_closed`: читают и меняют один общий флаг открытого состояния на узле.
- `can_be_toggled`: переключает хранимое Boolean-состояние.
- `can_be_used`: считает успешные применения и соблюдает лимит.
- `has_interaction_range`: проверяет дистанцию между двумя `Node2D`.
- `shows_interaction_prompt`: возвращает текст подсказки внутри указанного радиуса.
- `supports_hold_interaction`: считает прогресс удержания по переданному `delta`, поддерживает отмену и выдаёт событие завершения.

## Контракт, который должен обеспечить Object Builder

1. Вызывать `bind_target(Node2D)` после создания объекта.
2. Подключать сигналы запросов к игровому контроллеру/обработчику взаимодействия.
3. Для подбора после получения `pickup_requested` выполнить фактический перенос в инвентарь, а затем вызвать `confirm_pickup(true)` или `confirm_pickup(false)`. Компонент не должен сам удалять объект до успешного приёма инвентарём.
4. Подключить `interaction_requested` к выбранному действию объекта (диалог, открытие окна, активация устройства и т. п.).
5. Обеспечить визуальную реакцию на `opened`, `closed`, `activated`, `deactivated` и `toggled`; компонент хранит состояние, но не предполагает конкретную анимацию или UI.
6. Периодически вызывать `update_prompt_visibility(interactor)` либо `get_prompt(interactor)` и отображать возвращённый текст в UI.
7. Во время удержания вызывать `advance_hold(delta)` только пока действие удерживается; на отпускании кнопки вызывать `cancel_hold()`.
8. Сериализовать metadata `object_builder_active_state`, `object_builder_open_state` и `object_builder_toggle_state`, если эти состояния должны переживать сохранение/загрузку.

## Ограничения и важные детали

- `can_interact` не проверяет радиус автоматически. Для такой проверки контроллер должен вызвать `has_interaction_range.require_in_range()` или использовать собственную политику выбора цели.
- `can_be_picked_up` не меняет инвентарь, не скрывает и не удаляет предмет. Он безопасно выдаёт запрос и ждёт подтверждения принимающей системы.
- Для компонентов `can_be_opened` и `can_be_closed` настройки `starts_open` должны быть согласованы. После первой записи metadata значение становится общим для всех компонентов на этом узле.
- Prompt-компонент возвращает строку и выдаёт сигнал видимости, но не создаёт Control-ноды и не рисует подсказку.
- `supports_hold_interaction` не читает ввод самостоятельно: управление нажатием/отпусканием принадлежит хосту.
- Состояния локальны узлу и не являются глобальной системой событий, очередью действий или системой сохранения.
