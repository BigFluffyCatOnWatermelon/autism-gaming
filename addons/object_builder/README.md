# Object Builder 0.4.2

Object Builder — редакторский плагин для создания определений игровых объектов. Он не является частью игрового цикла: библиотека и runtime API продолжают работать, даже если плагин выключен.

## Возможности первой версии

- Мастер создания: выбор типа (NPC, ресурс, конструкция, предмет, оружие, инструмент, животное, интерактивный объект, декорация, транспорт, эффект или универсальная заготовка) до открытия формы редактирования.
- Для каждого типа задаются подходящие категория библиотеки, корневой узел и начальный набор параметров, сгруппированных по назначению.
- Создание пустого объекта с корневым узлом Node2D, StaticBody2D, Area2D, CharacterBody2D, RigidBody2D или AnimatableBody2D.
- Создание нового объекта на основе встроенного или пользовательского шаблона.
- Название, постоянный ID, категория, теги и описание.
- Пользовательские свойства типов String, Integer, Float, Boolean и Vector2.
- Повторное редактирование свойств без смены постоянного ID: тип, подпись, default, группа, описание.
- Пометка дополнительных настроек и min/max для числовых Integer/Float-свойств с проверкой при сохранении.
- Сохранение определения в библиотеку и автоматическое создание базовой сцены.
- Открытие созданной сцены в редакторе Godot для добавления спрайтов, коллизий и других узлов.
- Поиск и фильтрация библиотеки по категориям и тегам.
- Избранное и последние 20 объектов с локальным хранением в метаданных редактора.
- Базовое дерево узлов открытой сцены выбранного объекта с синхронизацией выделения со штатными Scene dock и Inspector.
- Обновление дерева и панели Sprite2D/AnimatedSprite2D при добавлении узлов и изменении их свойств через обычный Inspector.
- Компактный список выбора дочернего узла с собственной прокруткой.
- Стартовые числовые и логические параметры типа редактируются прямо в списке; прочие — через диалог свойства.
- Добавление и удаление дочерних узлов с поддержкой штатного Undo/Redo.
- Дочерний узел `ObjectProperties` с сериализуемыми определениями и значениями пользовательских свойств.
- Динамические типизированные поля Inspector для пользовательских свойств; поддерживаются группы и числовые min/max.
- Runtime API, который читает и меняет те же поля `ObjectProperties`, а не отдельную копию значений.
- Каталог компонентов с категориями Appearance/Physics/Stats/Combat/Interaction/Destruction/Audio/Procedural и выбором доступных компонентов.
- Редактор списка компонентов: добавление, включение/отключение и удаление компонентов из определения объекта.
- Типизированные настройки компонентов в штатном Inspector; схема полей и значения сохраняются в ресурсе ObjectDefinition.
- Панель визуального редактора Sprite2D с предпросмотром текстуры, выбором изображения, сеткой кадров, смещением, центрированием и отражением.
- Поддержка AnimatedSprite2D/SpriteFrames: загрузка ресурса, выбор анимации и кадра, предпросмотр кадра, Speed Scale от -10 до 10.

## Использование

1. Открой Project → Project Settings → Plugins и убедись, что Object Builder включён.
2. Открой док Object Builder справа в редакторе.
3. Нажми «Новый» и сначала выбери тип объекта. Подсказка покажет назначение, корневой узел и число стартовых параметров.
4. После подтверждения проверь название, категорию и тип корневого узла. Для выбранного типа будут созданы стартовые параметры, сгруппированные по смыслу.
5. Числовые и логические параметры можно менять прямо в списке, остальные — через кнопку с карандашом. Нажми «Сохранить в библиотеку».
6. Нажми «Открыть сцену». Новые сцены сразу содержат дочерний узел `ObjectProperties`. Для существующей сцены после открытия нажми «Сохранить в библиотеку» ещё раз: Object Builder добавит или обновит этот узел, не меняя существующие игровые узлы.
7. Выбери «Параметры объекта» (`ObjectProperties`) в дереве Object Builder или штатном Scene dock. В Inspector появятся типизированные поля пользовательских свойств, сгруппированные по назначению. Меняй их в Inspector или через ObjectFactory — обе стороны работают с одними значениями.
8. После изменений нажми Ctrl+S: определения и значения `ObjectProperties` сохраняются в `.tscn`. Значения пока не подключены к отдельным игровым save-файлам.
9. Выбери узел в дереве Object Builder или штатном Scene dock — выделение синхронизируется в обе стороны. Кнопка «+ Дочерний узел» открывает ограниченный по высоте список типов с внутренней прокруткой.
10. При выборе Sprite2D в любом из двух деревьев появится панель визуального редактора. Изменения Texture, H/V Frames, Frame, Offset, Centered и Flip H/V через Inspector сразу обновляют панель; изменения через панель применяются к тому же узлу и видны в Inspector. Назначь изображение кнопкой «Обзор…» или введи путь res://; настрой H/V, кадр, смещение, центрирование и Flip H/V.
11. При выборе AnimatedSprite2D назначь ресурс SpriteFrames через «SpriteFrames…», затем выбери анимацию и кадр; предпросмотр показывает выбранный кадр. Speed Scale можно менять от -10 до 10 (отрицательное значение — обратное направление).
12. Изменения дерева и визуальных параметров поддерживают Ctrl+Z/Ctrl+Y. Сохраняй сцену через Ctrl+S.

Флажок «Сохранить как шаблон» превращает новую заготовку в пользовательский шаблон. Существующие объекты из библиотеки нельзя случайно переключить в шаблоны: это защищает от перемещения и потери записи.

## Структура данных

- data/object_library/objects — определения игровых объектов.
- data/object_library/templates — встроенные и пользовательские шаблоны.
- data/object_library/scenes — сцены объектов.
- scripts/object_system — runtime-модель, фабрика и реестр.
- addons/object_builder — только редакторский интерфейс.

Избранное и недавние объекты хранятся в проектных метаданных Godot EditorSettings вне папки проекта. Повторное сохранение существующего определения создаёт рядом резервную копию с расширением .bak. Файлы резервных копий не загружаются как объекты библиотеки.

Для AnimatedSprite2D выбери узел в дереве, назначь SpriteFrames через кнопку «SpriteFrames…», затем выбери анимацию и кадр. Предпросмотр показывает выбранный кадр; Speed Scale задаёт темп, отрицательное значение — обратное направление. Autoplay и Loop Mode пока настраиваются через штатный Inspector Godot.

## Компоненты в Object Builder

1. Выбери объект в библиотеке или создай новый.
2. В блоке «Компоненты» выбери категорию «Характеристики», затем компонент «Здоровье» и нажми «+ Добавить».
3. В списке компонентов можно снять флажок, чтобы временно отключить компонент, или нажать «×», чтобы удалить его из определения.
4. Нажми «Inspector» напротив компонента. В штатном Inspector откроются его настройки: максимальное и начальное здоровье, неуязвимость и разрешение лечения. Числовые поля имеют заданные диапазоны.
5. После правок вернись в Object Builder и нажми «Сохранить в библиотеку». Настройки компонента записываются в `ObjectDefinition` (`.tres`), а не в отдельный игровой save-файл.

При создании runtime-экземпляра `ObjectFactory` добавляет включённые компоненты к корневому узлу. Они не создаются как дочерние узлы редактируемой `.tscn`: их состав определяется ресурсом объекта. Сейчас доступен только Health; остальные категории отображаются как будущие разделы каталога. Health пока не подключён автоматически к существующим Player и ResourceNode.

## Runtime API

Создай ObjectRegistry, добавь его в дерево сцены и вызови instantiate_by_id:

    var registry := ObjectRegistry.new()
    add_child(registry)
    var tree := registry.instantiate_by_id("object_id", $World/Objects)

Пользовательские значения доступны через ObjectFactory.get_custom_property(node, property_id, fallback), ObjectFactory.get_custom_property_definition(node, property_id) и ObjectFactory.set_custom_property(node, property_id, value). `set_custom_property()` возвращает bool: неправильный тип или неизвестный ID отклоняется, значение Integer/Float за min/max ограничивается. Некорректный override при создании заменяется default. Значения хранятся в `ObjectProperties` и сохраняются в `.tscn` вместе с узлом; запись этих значений в игровые save-файлы пока не подключена.

Первый runtime-компонент — Health. Подключение по постоянному ID выглядит так:

    var health_definition := ObjectComponentCatalog.create_definition("health")
    health_definition.settings["max_health"] = 150.0
    health_definition.settings["starting_health"] = 150.0
    object_definition.components.append(health_definition)

    var instance := ObjectFactory.instantiate(object_definition)
    var health := ObjectFactory.get_component(instance, "health") as HealthComponent
    health.apply_damage(10.0)

Каталог задаёт defaults, а `settings` определения объекта переопределяет отдельные ключи. У Health доступны `apply_damage()`, `heal()`, `set_current_health()`, `set_max_health()`, `reset_health()`, `is_alive()` и `get_health_ratio()`. Сигналы: `health_changed`, `damaged`, `healed`, `died`. Добавление, отключение, удаление и редактирование настроек компонента доступны через панель «Компоненты» Object Builder. Health пока не управляет существующими Player или ResourceNode.

Плагин пока не переносит существующие ResourceNode и сцены Cozy Village автоматически. Не включай автоматическую миграцию: сначала создай копии и проверь объекты вручную.
