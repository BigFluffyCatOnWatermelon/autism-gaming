# Object Builder 0.8.0-dev

> **Сложность — внутри. Простота — снаружи.**

Цель — универсальный конструктор, которым сможет пользоваться новичок без знания Godot: внешний вид → возможности → настройки → попробовать → сохранить.

**Статус ветки 0.8.0-dev:** каталог содержит 200 механик в 20 разделах. Пять механик поддерживаются runtime; остальные 195 помечены «В разработке» и не включаются. Стабильная версия main 0.7.0 по-прежнему содержит четыре реализованные механики.

Это начальная рабочая версия простого режима, а не весь целевой конструктор. Полный план находится в [OBJECT_BUILDER_ROADMAP.md](../../OBJECT_BUILDER_ROADMAP.md), интерфейсная спецификация — в [OBJECT_BUILDER_UI_SPEC.md](../../OBJECT_BUILDER_UI_SPEC.md).

## Реализованные функции версии 0.7.0

### Библиотека и модель
- Библиотека определений, поиск, фильтры, избранное и последние объекты.
- Мастер создания с 12 профилями из ObjectCreationProfileRegistry, пунктом «Без профиля», шаблонами, постоянным ID и метаданными.
- Профили предлагают стартовые параметры, но не ограничивают дальнейшие возможности; реестр поддерживает регистрацию пользовательских профилей.
- ObjectDefinition schema 5, пользовательские свойства String, Integer, Float, Boolean и Vector2.
- Сохранение определений и сцен объектов, резервные копии.

### Простой режим
- Вкладки «Простой режим» и «Расширенный режим».
- Поля названия и описания, область миниатюры и кнопка «Добавить изображение».
- Поиск и фильтр по 20 категориям каталога механик.
- Библиотека содержит 200 карточек: пять работающих механик (в 0.8.0-dev) и 195 записей со статусом «В разработке».
- Карточки показывают состояние. Для будущих механик переключатель и настройки отключены, чтобы не добавлять пустое поведение.
- Переключатели включения и простые диалоги настроек.
- Автоматическое разрешение базовой зависимости Health для получения урона и разрушения.
- План изменения выбора возможностей проверяет зависимости, блокирует опасное отключение и поддерживает Undo/Redo.
- Кнопка «Сохранить объект» синхронизирует и сохраняет открытую сцену с определением.

### Расширенный режим и runtime
- Базовое дерево сцены и синхронизация со штатными Scene dock и Inspector.
- Панели Sprite2D и AnimatedSprite2D/SpriteFrames.
- Ручной каталог Health, Damageable, Attack, Destructible и Pickup.
- Component Binding позволяет размещать компоненты на разных узлах одного объекта; прежние определения с компонентами на корне остаются совместимыми.
- Поиск компонентов в пределах дерева одного объекта и межузловое взаимодействие Health/Damageable/Destructible.
- ObjectFactory загружает актуальную сцену по scene_path, если файл доступен.

### Окна и диалоги
- Все диалоги Object Builder используют общий ограничитель по рабочей области монитора.
- Окна создания, выбора шаблона, свойств, настроек возможностей, выбора текстур/SpriteFrames и добавления узлов открываются ограниченными и центрированными.
- Длинные настройки возможностей и свойства помещаются в прокручиваемые формы.

## Библиотека механик версии 0.7.0

- Полный перечень всех 200 записей, их описания и ID: [MECHANICS_CATALOG.md](../../MECHANICS_CATALOG.md).
- Пять доступных механик в ветке 0.8.0-dev: здоровье, получение урона, атака, разрушение при потере здоровья и подбор предмета.
- 195 остальных записей — будущие модули каталога, а не готовое runtime-поведение. Они показываются в списке и доступны для поиска, но включить их пока нельзя.
- Новые механики переводятся в доступные только после реализации и прохождения smoke-тестов.

## Известные ограничения версии 0.7.0

- Интерфейс пока расположен в правом dock, не в центральной главной вкладке Godot.
- Библиотека отображается списком; иллюстрированные карточки и коллекции ещё не реализованы.
- Выбор профиля пока представлен обычным списком, а не иллюстрированными карточками; отдельного визуального редактора пользовательских профилей ещё нет.
- «Добавить изображение» создаёт Sprite2D и открывает выбор текстуры. Перетаскивание, масштабирование и вращение частей внутри собственного canvas ещё не реализованы.
- Из 200 записей в ветке 0.8.0-dev пять имеют runtime-поведение; 195 ждут реализации соответствующих компонентов и сценариев. Pickup пока не связан с инвентарём игрока.
- Полноценный Preview черновика, визуальный редактор коллизий/точек крепления, редактор событий/состояний, Instance Overrides и выборочное обновление ещё не реализованы.
- Headless CI проверяет импорт, разбор скриптов, runtime smoke-тесты и запуск основной сцены, но не измеряет геометрию popup-окон. Оконные размеры и прокрутку следует вручную проверить в Godot GUI на разных разрешениях.

## Использование версии 0.7.0

1. Включи Object Builder в Project → Project Settings → Plugins.
2. Открой dock Object Builder.
3. Нажми «Создать объект» и выбери стартовый профиль или «Без профиля». Профиль предлагает начальные значения, но не ограничивает будущие возможности.
4. Перейди на вкладку «Простой режим», укажи название и описание.
5. Нажми «Добавить изображение»: плагин создаст Sprite2D и откроет выбор текстуры. Пока положение/масштаб меняются в стандартном 2D-редакторе Godot.
6. В блоке «Что должен уметь объект?» используй поиск и 20 категорий. Включать можно карточки со статусом «Готово»; карточки «В разработке» пока доступны только для просмотра.
7. Кнопка «Настроить» открывает параметры работающей возможности. Необходимые базовые зависимости подключаются автоматически.
8. Нажми «Сохранить объект». Если сцена объекта открыта, она синхронизируется и сохраняется до записи определения библиотеки.
9. Для ручной работы с деревом сцены, Inspector, свойствами и компонентами открой «Расширенный режим».

## Структура данных

- data/object_library/objects — определения игровых объектов.
- data/object_library/templates — встроенные и пользовательские шаблоны.
- data/object_library/scenes — сцены объектов.
- scripts/object_system — runtime-модель, фабрика и реестр.
- addons/object_builder — только редакторский интерфейс.

Избранное и недавние объекты хранятся в проектных метаданных Godot EditorSettings вне папки проекта. Повторное сохранение существующего определения создаёт рядом резервную копию с расширением .bak. Файлы резервных копий не загружаются как объекты библиотеки.

Для AnimatedSprite2D выбери узел в дереве, назначь SpriteFrames через кнопку «SpriteFrames…», затем выбери анимацию и кадр. Предпросмотр показывает выбранный кадр; Speed Scale задаёт темп, отрицательное значение — обратное направление. Autoplay и Loop Mode пока настраиваются через штатный Inspector Godot.

## Компоненты в Object Builder

1. Выбери объект в библиотеке или создай новый.
2. Добавь Health в категории «Характеристики».
3. Для объектов, которые должны принимать урон, добавь Damageable в категории «Бой». Он требует Health на том же объекте.
4. Для атакующего объекта добавь Attack. Настрой урон, дистанцию, перезарядку и проверку дистанции. Цель должна иметь Damageable, а тот — Health.
5. Для объекта, который должен разрушаться при потере здоровья, добавь Destructible из категории «Разрушение». Он реагирует на Health.died, отключает коллизии и получение урона, выдаёт сигнал destroyed. По умолчанию объект не скрывается и не удаляется: собственная сцена может проиграть падение дерева, показать пень, создать эффекты и предметы. В Inspector доступны скрытие/удаление, задержка удаления и восстановление через runtime API.
6. Сними флажок компонента, чтобы отключить его, или нажми «×», чтобы удалить из определения.
7. Кнопка «Inspector» открывает контекстные настройки. У Health это максимальное/начальное здоровье, неуязвимость и лечение. У Damageable — приём урона, множитель и плоское снижение. У Attack — урон, дистанция, cooldown, проверка расстояния и разрешение атаки. У Destructible — условие разрушения, отключение коллизий/урона, скрытие, удаление и восстановление здоровья.
8. После правок вернись в Object Builder и нажми «Сохранить в библиотеку». Настройки записываются в ObjectDefinition (.tres).

При создании runtime-экземпляра ObjectFactory размещает новые компоненты на узлах, указанных в Component Bindings. Старые определения без привязок продолжают добавлять компоненты к корню объекта. Компоненты могут находиться на разных узлах и находят друг друга через общий корень объекта. Damageable ищет Health в пределах объекта-цели; Attack вызывает Damageable у цели и проверяет собственные cooldown/дистанцию; Destructible подписывается на Health.died. Destructible не задаёт уникальную анимацию разрушения и не удаляет объект по умолчанию — дерево, камень или другой объект управляет своей визуальной последовательностью через сигнал destroyed. Attack пока не заменяет анимации и управление атаками игрока и не подключён к Player или ResourceNode.


### Pickup — подбор предмета

1. В простом режиме включи возможность «Подбираемый предмет».
2. В её настройках укажи ID предмета из каталога и начальное количество.
3. В принимающем объекте реализуй метод `receive_pickup(item_id, amount, source)`. Метод возвращает `true`, если принята вся стопка, или целое число принятых единиц для частичного подбора; `false`/0 означает отказ.
4. `PickupComponent.try_pickup(receiver)` возвращает фактически принятое количество. Остаток остаётся в мире. Когда стопка пуста, компонент запрещает дальнейший подбор и по настройке удаляет исходный объект.

Компонент не привязан к конкретному инвентарю. Интеграция с игровым инвентарём и вызов подбора от игрока пока остаются следующей задачей.

## Runtime API

Создай ObjectRegistry, добавь его в дерево сцены и вызови instantiate_by_id:

    var registry := ObjectRegistry.new()
    add_child(registry)
    var tree := registry.instantiate_by_id("object_id", $World/Objects)

Пользовательские значения доступны через ObjectFactory.get_custom_property(node, property_id, fallback), ObjectFactory.get_custom_property_definition(node, property_id) и ObjectFactory.set_custom_property(node, property_id, value). `set_custom_property()` возвращает bool: неправильный тип или неизвестный ID отклоняется, значение Integer/Float за min/max ограничивается. Некорректный override при создании заменяется default. Значения хранятся в `ObjectProperties` и сохраняются в `.tscn` вместе с узлом; запись этих значений в игровые save-файлы пока не подключена.

Runtime-пример: получить Damageable у созданного объекта и передать ему урон:

    var health_definition := ObjectComponentCatalog.create_definition("health")
    var damageable_definition := ObjectComponentCatalog.create_definition("damageable")
    object_definition.components = [health_definition, damageable_definition]

    var instance := ObjectFactory.instantiate(object_definition)
    var damageable := ObjectFactory.get_component(instance, "damageable") as DamageableComponent
    var applied_damage := damageable.receive_damage(20.0, attacker)

Каталог задаёт defaults, а `settings` определения объекта переопределяет отдельные ключи. У Health доступны `apply_damage()`, `heal()`, `set_current_health()`, `set_max_health()`, `reset_health()`, `is_alive()` и `get_health_ratio()`; сигналы: `health_changed`, `damaged`, `healed`, `died`. Damageable предоставляет `receive_damage(amount, source)`, возвращает фактически снятое здоровье, применяет формулу `max(0, amount * damage_multiplier - flat_reduction)` и выдаёт сигналы `damage_received` / `damage_blocked`. Attack предоставляет `perform_attack(target, source)`: проверяет включение, cooldown, дистанцию (если включена), наличие Damageable у цели и передаёт ей урон. Его сигналы — `attack_performed` и `attack_failed`. Все компоненты настраиваются через панель «Компоненты» Object Builder.

Плагин пока не переносит существующие ResourceNode и сцены Cozy Village автоматически. Не включай автоматическую миграцию: сначала создай копии и проверь объекты вручную.
