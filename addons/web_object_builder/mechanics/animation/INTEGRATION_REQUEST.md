# Запрос интеграции: animation

## Реализовано внутри пакета

- Компоненты 21–26 проверяют наличие именованной анимации в привязанном `AnimationPlayer` и запускают её.
- Компонент 27 вызывает `AnimationPlayer.play()` с настраиваемым blend time.
- Компонент 28 подписывается на `animation_started` и `animation_finished`, а также позволяет отправить пользовательский marker.
- Компонент 29 подписывается на `AnimatedSprite2D.frame_changed` и фильтрует индексы кадров.
- Компонент 30 читает JSON-таблицу вариантов и запускает сопоставленную анимацию.

## Что нужно от ядра

1. Подтвердить, как `ObjectComponent` получает ссылку на визуальную часть объекта.
2. При создании/восстановлении компонента вызвать `bind_animation_player(AnimationPlayer)` для компонентов 21–28 и 30 либо `bind_animated_sprite(AnimatedSprite2D)` для 29.
3. Обеспечить единый источник анимаций для `AnimationPlayer` и `AnimatedSprite2D` (при необходимости — адаптер). Не вызывать методы без проверки типа/наличия целевого узла.
4. Для событий кадров, которые должны вызывать игровые действия из редактора, создать явную таблицу frame markers и подключить её к `frame_event`.
5. Проверить конфликт между одновременными animation-командами (например, `play_attack` и `play_hit`) на уровне арбитража состояний.

Никакой неизвестный API ядра здесь не предполагается. Компоненты работают только после явной передачи валидного узла.
