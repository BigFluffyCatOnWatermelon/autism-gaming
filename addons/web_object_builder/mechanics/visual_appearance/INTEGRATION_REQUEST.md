# Требования к интеграции: visual_appearance

Пакет содержит десять самостоятельных компонентов. Они используют публичные методы Godot для `Sprite2D`, `CanvasItem`, `Node2D`, `Control`, `Node`, `Texture2D`, `Image` и `ShaderMaterial`. Пакет не обращается к конкретной игровой сцене или объекту игрока.

Для полной интеграции Object Builder требуется:

1. Подтвердить, что ядро вызывает `_on_configured()` после передачи настроек.
2. Предоставить каждому компоненту целевой узел или явную привязку из ObjectDefinition. Вызовы `apply_to()`/`set_direction()`/`create_shadow()` должны выполнять адаптеры ядра или явные пользовательские действия.
3. Для `has_multiple_visual_parts` передавать корневой `Node` и разрешать перечисленные `NodePath` только внутри текущего объекта.
4. Не добавлять визуальные узлы в исходное определение шаблона при предпросмотре; изменения должны применяться к экземпляру/черновику с поддержкой Undo/Redo.
5. При удалении временного эффекта тени удалять созданный `Sprite2D`; при снятии обводки вызывать `remove_from()`.
6. Для динамического сохранения настроек/состояния использовать `export_runtime_state()` и `import_runtime_state()` из базового компонента.

Ограничения текущей реализации: смена палитры работает с точной заменой RGBA-цветов исходной текстуры; она создаёт runtime-копию `ImageTexture` и не перезаписывает файл на диске. Обводка использует 8 соседних выборок текстуры. Тень создаётся отдельным Sprite2D и требует родительский узел у источника.
