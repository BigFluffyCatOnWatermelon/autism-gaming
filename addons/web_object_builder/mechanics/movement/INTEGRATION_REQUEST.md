# Запрос интеграции: movement

## Реализовано внутри пакета

- Компоненты 31–33 и 36, 37, 38 принимают направление и шаг времени, валидируют вход и перемещают `Node2D`; для `CharacterBody2D` используется `velocity` + `move_and_slide()`, для прочего `Node2D` — изменение `global_position`.
- Компонент 34 выполняет плавный Tween-прыжок и возвращает объект на исходную локальную высоту.
- Компонент 35 выполняет Tween-рывок, проверяет перезарядку и не допускает параллельный рывок.
- Компонент 39 телепортирует объект в точку после проверки координат и максимального радиуса.
- Компонент 40 следует по последовательности координат, поддерживает зацикливание и сигналы прибытия/завершения.

## Что нужно от ядра

1. Передавать компонентам ссылку на корневой `Node2D` через `bind_target(Node2D)`.
2. Для `can_move`, `can_walk`, `can_run`, `can_fly`, `can_swim` и `can_climb` вызывать соответствующую команду в физическом цикле и передавать `delta`.
3. Создать арбитраж команд движения: одновременно включённые режимы не должны независимо перемещать один и тот же объект в одном physics tick.
4. Для `CharacterBody2D` вызывать команды только из физического цикла. Текущая реализация для обычного `Node2D` изменяет позицию напрямую и не обеспечивает столкновения.
5. Прыжок и рывок сейчас являются позиционными Tween-анимациями. Для collision-safe движения нужно предоставить единый motion adapter (например, запрос перемещения с проверкой столкновений).
6. Патрульный маршрут использует координаты глобального пространства, заданные как JSON-массив пар чисел. При загрузке сцен ядро должно определить, в каком пространстве хранятся маршрутные точки.
7. Состояние перезарядки рывка и активного патруля при необходимости сохранять через `export_runtime_state()`; текущее состояние патруля намеренно не восстанавливает Tween-процессы.

Не предполагается никакой неизвестный метод ядра: привязка и команды открыты как явные публичные методы пакета.
