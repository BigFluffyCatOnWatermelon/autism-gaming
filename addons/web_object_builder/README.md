# Web Object Builder

**Активный редакторский плагин проекта.** Включается через res://addons/web_object_builder/plugin.cfg; старый плагин addons/object_builder теперь архивный и не требуется.

## Состав

- plugin.gd — центральная вкладка Web Object Builder, встроенный WebView и собственный dock «Библиотека объектов».
- services/object_builder_backend.gd — команды, черновики, сохранение и синхронизация с моделью Object System.
- services/object_creation_service.gd, library_actions_service.gd, scene_draft_service.gd — создание записей, копирование/удаление, создание и синхронизация настоящих PackedScene.
- ui/object_library_dock.gd, ui/object_library_tree.gd и ui/object_library_preview_grid.gd — самостоятельная панель библиотеки с поиском, категориями, древовидным и thumbnail-режимом, открытием объекта, переходом к сцене и перетаскиванием на 2D-холст. Сервис services/library_drag_service.gd готовит PackedScene для системного file-drag Godot.
- mechanics/ — пакеты механик, которые регистрирует MechanicModuleLoader. Старый каталог механик оставлен как архивная копия; активная загрузка идёт из этого каталога.
- Sprite editor поддерживает масштабирование спрайта от центра при удержании Alt; Shift фиксирует пропорции, Ctrl временно отключает привязку.
- Удары игрока работают с объектами, у которых включены Health и Damageable. Материал и требуемый инструмент определяют допустимость попадания; разрушение может включать покачивание/падение, частицы, звук, лут, обломки и остатки.
- Сцены, перетащенные напрямую из библиотеки в Godot, сохраняют `ObjectBuilderReference`. При запуске игры этот узел загружает ObjectDefinition и автоматически подключает runtime-механики к уже размещённому корню через `ObjectFactory.initialize_existing_instance()`, без замены визуальных узлов или их трансформаций.
- Runtime-удар проверяет ближайшую точку видимого спрайта как у legacy ResourceNode, так и у новых Object Builder объектов. Материал, требуемый инструмент и радиус находятся в Damageable settings; добыча — в loot table механики drops_loot_on_destroy.
- Legacy-свойства материала/инструмента/радиуса/выпадающего предмета автоматически переносятся в соответствующие настройки при открытии библиотеки. Остальные пользовательские свойства сохраняются.
- В списке подключённых механик есть отдельная кнопка «Настроить»: параметры редактируются в модальном окне выбранной механики, а связи добычи/остатков/производства остаются внутри этого окна.
- web/ — интерфейс конструктора.

## Зависимости

Нужен Godot WRY (addons/godot_wry/WRY.gdextension) и WebView2 Runtime в Windows. Плагин Object Builder включать не нужно. Он помечен как архивный и не создаёт старый интерфейс.

Плагин самостоятельно регистрирует отдельный EditorDock «Библиотека объектов» в левой верхней области редактора и пункт меню Проект → Инструменты → Открыть библиотеку объектов. Пункт меню открывает и фокусирует именно этот dock. Старый плагин Object Builder не требуется.

## Хранение данных

Единственный постоянный источник объектных данных — ObjectDefinition из scripts/object_system/. Веб-интерфейс не хранит библиотеку в localStorage.

Встроенные ресурсные шаблоны библиотеки: `tree_oak_summer.tres`, `tree_pine_summer.tres`, `tree_oak_autumn.tres`, `tree_pine_autumn.tres` и `rock_large.tres`. Они уже содержат Preview Texture, коллизию и включённые runtime-механики. Прочность задаётся через Health, материал/инструмент/радиус — через Damageable, а выпадение — через таблицу drops_loot_on_destroy; устаревшие системные custom properties в шаблонах не используются.

Новые записи используют читаемые ASCII-имена файлов, построенные из названия объекта:

- res://data/object_library/objects/<category>/<object_name>.tres
- res://data/object_library/templates/<category>/<object_name>.tres
- res://data/object_library/scenes/objects/<category>/<object_name>.tscn
- res://data/object_library/scenes/templates/<category>/<object_name>.tscn

Например, «Сосна» сохраняется как `sosna.tres` и `sosna.tscn`, «Древесина» — как `drevesina.tres` и `drevesina.tscn`. Кириллица транслитерируется, пробелы и знаки пунктуации нормализуются. Постоянный `object_id` хранится внутри ObjectDefinition и метаданных сцены, а не используется как имя файла. При конфликте имён библиотека подбирает уникальное имя с числовым суффиксом.

При переименовании объекта его .tres и .tscn перемещаются на новые имена, постоянный ID и связи сохраняются. Старые ID-based файлы, а также промежуточные каталоги с кириллическими именами (Объекты, Сцены, Шаблоны), мигрируют при первой инициализации Web Object Builder. Перенос сцены и ObjectDefinition выполняется с резервированием/восстановлением прежней сцены при ошибке записи.

## Связи и сохранение копий

При добавлении связанного объекта Web Builder сначала использует существующую запись из библиотеки. Совпадение проверяется по исходному template ID, затем по точному названию и категории. При сохранении backend ещё раз проверяет связанные черновики и перенаправляет совпадающие связи на уже существующий object_id, не создавая повторную запись.

Кнопка «Сохранить как» (Ctrl+Shift+S) создаёт независимую копию текущего объекта: новый ObjectDefinition, новый ID и отдельную PackedScene. Свойства, компоненты, механики, спрайты и связи копируются; исходная запись не перезаписывается. Связанные черновики, для которых нет сохранённой цели, сначала нужно сохранить отдельно.

## Открытие библиотеки

Dock появляется слева после загрузки Web Object Builder. Его можно повторно открыть командой Проект → Инструменты → Открыть библиотеку объектов. Для работы библиотеки не требуется запускать старый Object Builder.

## Встроенный WebView

Плагин создаёт WRY WebView после добавления native Control в дерево редактора. При создании отключён автоматический захват фокуса WebView2, поскольку переключение главной вкладки Godot может временно блокировать фокус окна; фокус передаётся после завершения загрузки страницы. Для профиля браузера используется `data_directory` WRY.

## Обновление библиотеки и синхронизация с Godot

- При сохранении сцена перечитывается через `ResourceLoader.CACHE_MODE_REPLACE_DEEP`, чтобы backend использовал обновлённый PackedScene.
- Даже если в Web Builder есть несохранённый черновик, профиль коллизии из Godot (включение, форма, размер, смещение, режим, слой и маска) объединяется с ним отдельно; остальные несохранённые поля браузера остаются нетронутыми.
- Web Builder отслеживает сохранение сцен через сигналы `EditorPlugin.scene_saved` и `resource_saved`. После сохранения сцена перечитывается с глубокой заменой кэша, управляемые спрайты и коллизии извлекаются обратно в `ObjectDefinition`, затем обновляются открытые документы Web Builder и нативный Dock. Повторное ручное обновление не требуется. Проверяются оба хранилища сцен — новый `data/object_library/scenes` и старый локализованный `data/object_library/Сцены`; связь восстанавливается по `scene_path` или ID корневого узла. Сцены шаблонов синхронизируются без преобразования шаблона в обычный объект.
- Копии `.tres` внутри `res://data/object_library/objects/**` распознаются по повторному `object_id`: копия получает новый ID и собственную сцену, исходная запись остаётся прежней.
- Новые `.tscn` внутри `res://data/object_library/scenes/objects/**` импортируются как самостоятельные объекты. Если сцена содержит ID известного объекта, она клонирует определение с новым ID; если нет — создаётся минимальное определение по сцене.
- В библиотеке Godot доступны два режима: «Список» и «Превью». В режиме превью миниатюра сцены загружается через EditorResourcePreviewer.
- В режиме «Превью» размер квадратной миниатюры настраивается прямо в dock: 64–256 px с шагом 8 px. Значение сохраняется в метаданных текущего проекта Godot.
- Коллизия задаётся как твёрдое тело (блокирует движение) либо Area2D (обнаруживает пересечение). Слой 2 предназначен для препятствий, маска 1 включает игрока; старые записи схемы 10 с профилем 1/1 мигрируют на совместимый с игроком слой 2.
- Для объектов библиотеки добавляется служебный контроллер сортировки по нижней точке объекта: его абсолютный Z рассчитывается из мировой координаты Y и высоты `object_size`. Внутренние спрайты сохраняют относительные Z-index: больший Z рисуется поверх меньшего. В редакторе спрайтов список показывает верхние слои первыми и доступны команды «На передний план» / «На задний план».
- Проектный CanvasItem filter установлен в Nearest (`rendering/textures/canvas_textures/default_texture_filter=0`); управляемые спрайты и визуальный контейнер дополнительно получают `TEXTURE_FILTER_NEAREST` явно.
- Перетаскивание передаёт редактору настоящий путь `.tscn` в том же формате `type=files / files / from`, который использует Scene Palette. До начала перетаскивания библиотека создаёт/синхронизирует PackedScene, если её ещё нет.
- Сохранение сцены объекта в Godot автоматически передаёт изменения управляемого основного спрайта, дополнительных слоёв и профиля коллизии в ObjectDefinition. Для коллизии считываются включение, режим `StaticBody2D`/`Area2D`, форма Rectangle/Circle/Capsule, размер или радиус/высота, смещение относительно корня объекта, физический слой и маска. Остальные вручную добавленные узлы показываются в дереве Web Builder как внешние, только для чтения; их путь и основные инспекторные свойства (позиция, видимость, трансформация, ресурсные ссылки и прочие поддерживаемые значения) также синхронизируются. Они остаются в сцене и не дублируются при сохранении из Web.
- Если рядом с копией .tres лежит скопированная сцена с тем же basename, импорт использует именно эту сцену как источник. Её собственные правки переносятся в новую независимую сцену; исходные файлы удаляются только после успешного сохранения новой записи и сцены.
- Сохранение самого `.tres` ObjectDefinition через Inspector Godot тоже передаётся в Web Builder. Чистый открытый документ перечитывается; если в Web Builder есть несохранённые правки этого же объекта, черновик не перезаписывается и отображается конфликт.
- После сохранения объекта в Web Builder обновлённые PackedScene перечитываются, а открытые сцены Godot, которые используют эти объекты, автоматически перезагружаются. Сцены с несохранёнными правками не перезагружаются, чтобы не потерять изменения; в таком случае выводится предупреждение.
- Если в Web Builder есть несохранённый черновик того же объекта, изменение сцены в Godot не перезаписывает этот черновик: конфликт показывается в Web интерфейсе.

Сканер намеренно импортирует только файлы из каталогов библиотеки объектов/сцен. Произвольные сцены игровых уровней и ассетов за пределами `data/object_library` не добавляются в библиотеку автоматически.
