- Smoke-тесты мастера, сервиса создания, импорта неизвестного содержимого, отчёта распознавания частей и сохранности исходной сцены добавлены в GitHub Actions. Текущий CI и ручная GUI-проверка после изменений ещё не подтверждены.

### Новое целевое направление UX — 2026-11-06

Главный тезис: **«Сложность — внутри. Простота — снаружи».**

Object Builder должен стать конструктором, которым сможет пользоваться новичок без знания Godot и программирования. Основной путь: **Внешний вид → Возможности → Настройки → Попробовать → Сохранить**. В простом режиме технические детали скрыты; расширенный режим открывает настоящую структуру Godot и полный контроль.

**Текущая версия Object Builder — 0.8.0-dev.** Библиотека содержит 200 механик: 42 доступны для включения, 158 остаются «В разработке». Все десять автономных пакетов подключены через MechanicModuleLoader API v1. Встроенные Pickup и Interactable добавляют частичный подбор предметов в существующий инвентарь и взаимодействие клавишей E.

Остальная базовая вертикаль сохраняется: простой/расширенный режимы, 12 профилей и «Без профиля», единый реестр компонентов, привязки к разным узлам, планирование зависимостей и безопасные диалоги. Object Builder перенесён в центральную вкладку Godot через Main Screen Plugin; библиотека и оба режима редактирования доступны в одном рабочем пространстве. Повторяемые поля, кнопки, заголовки, пустые состояния, формы диалогов и очистка списков вынесены в ObjectBuilderUIFactory. Библиотека объектов и оболочка простого/расширенного редактора выделены в независимые компоненты LibraryView и ObjectEditorView с отдельными smoke-тестами. Сборка экранов разделена на отдельные функции. Карточная библиотека, Canvas и изолированный Preview реализованы; ручная GUI-проверка на широком и узком разрешении остаётся обязательной.

### Внутренняя архитектура Object Builder — 2026-11-07

- `LibraryController` владеет данными библиотеки: загрузкой, фильтрами, поиском, сортировкой, избранным, недавними объектами и шаблонами.
- `ObjectEditorSession` владеет черновиком определения, независимым исходным снимком, состоянием нового объекта и признаком несохранённых изменений. Сброс восстанавливает исходный снимок; успешное сохранение фиксирует новую базовую версию.
- `SceneDraftService` создаёт базовую сцену объекта и копирует сцену шаблона. Он работает с ресурсами Godot и не обращается к `EditorInterface`.
- `plugin.gd` остаётся координатором UI и интеграции со штатным редактором Godot; представления, данные библиотеки, сессия объекта и подготовка PackedScene вынесены в отдельные модули.

### Рабочее пространство Object Builder — 2026-11-07

## Объекты и мир

- Деревья и камни, размещённые из CozyVillage, генерируются как разрушаемые ResourceNode со своими исходными текстурами; деревья падают и оставляют пень, камни покрываются трещинами и рассыпаются.
- Разрушаемые ResourceNode обнаруживаются по всему дереву сцены World, независимо от родительского узла; новые объекты также регистрируются при добавлении во время игры.
- Игрок сортируется по координате ног; ResourceNode и обычные placeable-сцены — по нижнему краю видимого спрайта (с учётом трансформации), чтобы корректно проходить за кронами и перед стволами.
- При запуске не создаются случайные деревья и камни.
- `World/Objects` пуст в стартовой сцене.
- Для ручного размещения используй сгенерированные `.tscn` в `scenes/environment_assets/Nature/Trees/` и `scenes/environment_assets/Nature/Rocks/`. Предпочтительно добавлять их в `World/Objects`, но регистрация работает и при размещении в другой ветке `World`.
- Дерево разделено на ствол и крону; после падения оставшаяся часть ствола отрисовывается процедурным пнём. Высота и ширина пня настраиваются на каждом ResourceNode в Inspector.
- При попадании по дереву/камню создаются пиксельные частицы с цветом, полученным из текстуры объекта. В ResourceNode доступны отдельные звуковые слоты для попадания и разрушения каждого типа ресурса.
- Выпавшие при добыче предметы разлетаются, отскакивают и притягиваются к игроку; ручной выброс из инвентаря начинается у ног игрока и летит в сторону курсора.
- Q выбрасывает выбранный стек у ног игрока в направлении курсора; drag-and-drop из инвентаря также задаёт направление броска.

- Диапазон применяется только к изолированной копии объекта: Canvas дублирует SpriteFrames и удаляет кадры вне выбранного включительного диапазона в копии ресурса. Исходный SpriteFrames и сохранённая сцена не изменяются.
- В копии сохраняются FPS и режим Loop (None/Linear/Ping-Pong); Play/Pause продолжает использовать штатный AnimatedSprite2D.
- При переключении выбранной части исходный ресурс preview восстанавливается, текущий кадр сопоставляется с исходной нумерацией; диапазоны сохраняются в памяти текущего Canvas-сеанса отдельно для выбранных NodePath.
- Добавлены smoke-проверки диапазона, независимости исходного ресурса, сохранения FPS и Ping-Pong.
- Требуются свежий успешный GitHub Actions и ручная проверка расположения полей и воспроизведения в Godot 4.7.2 GUI.


### Улучшение каталога и настроек механик — 2026-11-08

- Каталог получил фильтр состояния (можно добавить / установлено / отключено / в разработке / выбрано) и сортировку по релевантности, алфавиту и готовности. Состояние множественного выбора хранится в прежней SelectionSession.
- Кнопка «Подробнее» доступна для всех карточек, а не только механик с графовыми отношениями. Панель фокуса показывает описание, статус готовности, категорию, обязательные зависимости и конфликты; локальная полоса отношений и полная карта сохранены.
- Панель настроек получила сворачиваемые группы, три уровня отображения, общий сброс, точный индикатор изменений и блокировку Apply без изменений/при ошибках.
- Для числовых значений с ограниченным небольшим диапазоном связаны HSlider и SpinBox; поле точного ввода остаётся доступным.
- Добавлены специализированные редакторы для String-схем: ColorPickerButton с обратной сериализацией в HTML-цвет, многострочный JSON с синтаксической проверкой, файловый выбор текстур и сцен. JSON- и scene-path подсказки также распознаются по стабильным именам ключей.
- Plugin применяет только изменённые настройки через существующий build_application_plan и сохраняет единую Undo/Redo-операцию.
- Добавлены/расширены smoke-тесты каталога и панели настроек. Результат GitHub Actions для итогового коммита и ручная проверка Godot 4.7.2 GUI ещё не подтверждены.
