# Object Builder — сценарий взаимодействия пользователя

**Главный тезис: «Сложность — внутри. Простота — снаружи».**

Этот документ описывает, что видит и делает пользователь. Он рассчитан на человека, который впервые открыл Godot и не умеет программировать. В обычном режиме пользователь не обязан знать термины «узел», «компонент», «сигнал», «сцена» или «NodePath».

Все примеры используют один универсальный конструктор. Сундук, меч, NPC, ресурс, снаряд или здание не требуют разных редакторов.

Статус: целевой пользовательский сценарий. Object Builder 0.5.3 содержит ранние вкладки простого/расширенного режима, карточки возможностей с планированием зависимостей и выбор стартового профиля или «Без профиля». Полный сценарий (иллюстрированный мастер, canvas, широкий каталог механик, Preview и работа с экземплярами) ещё находится в дорожной карте.

Подробное описание того, из каких элементов состоят экраны и что делает каждая кнопка/панель/строка/поле, см. в OBJECT_BUILDER_UI_SPEC.md. Если здесь описан сценарий, а там — конкретный UI-элемент, документы дополняют друг друга.

## 1. Открытие Object Builder

Пользователь нажимает вкладку Object Builder.

Он видит библиотеку — большие карточки сохранённых объектов, поиск и кнопку **«Создать объект»**.

На экране нет дерева узлов, списка технических компонентов или длинного перечня настроек. Пользователь может открыть существующий объект, сделать копию, выбрать шаблон или начать с нуля.

Основные действия библиотеки:
- Создать объект.
- Открыть объект.
- Дублировать.
- Создать из шаблона.
- Импортировать.
- Найти по названию или по тому, что объект умеет делать.

Избранное, недавние объекты и категории не мешают основному экрану и могут быть компактными фильтрами.

## 2. Создание нового объекта

### Шаг 1. Нажать «Создать объект»

Появляется четыре понятные карточки:
- С нуля.
- Из шаблона.
- Копия существующего.
- Импортировать сцену.

Пользователь выбирает «С нуля».

### Шаг 2. Выбрать примерную категорию

Появляются крупные иллюстрированные карточки:
- Предмет.
- Ресурс.
- Оружие.
- Инструмент.
- Персонаж.
- NPC.
- Животное.
- Контейнер.
- Механизм.
- Постройка.
- Эффект.
- Другое.

Рядом есть «Не знаю — начать с обычного объекта».

Пользователь выбирает «Контейнер». Плагин лишь предлагает подходящие стартовые настройки. Это не ограничивает дальнейшие возможности: контейнер может атаковать, двигаться, разрушаться или делать что-то ещё, если пользователь этого захочет.

Плагин самостоятельно выбирает техническую основу и создаёт внутренний ID. Пользователь не выбирает класс Godot и не должен понимать устройство сцены.

## 3. Внешний вид

Открывается большая рабочая область с подсказкой **«Добавь изображение своего объекта»**.

Пользователь перетаскивает картинку сундука из файлов или выбирает её в проекте.

Сразу появляется изображение. Его можно:
- передвинуть мышью;
- увеличить или уменьшить;
- повернуть;
- выбрать другое изображение;
- добавить ещё одну часть.

Пользователь добавляет изображение крышки как отдельную часть и передвигает её на нужное место. При необходимости нажимает «Анимация» и выбирает готовую анимацию или просит создать простое движение автоматически.

Он видит результат непосредственно на рабочем поле. Не нужно открывать дерево сцены или искать Sprite2D.

## 4. Выбор того, что объект умеет

Плагин спрашивает:

**«Что должен уметь этот сундук?»**

Пользователь видит карточки с понятными описаниями:
- Открывать и закрывать.
- Хранить предметы.
- Быть запертым.
- Издавать звуки.
- Получать урон.
- Разрушаться.
- Взаимодействовать с игроком.

Пользователь выбирает:
- Открывать и закрывать.
- Хранить предметы.
- Взаимодействовать с игроком.

Плагин показывает короткое подтверждение: «Добавим открытие сундука, хранение предметов и взаимодействие с игроком». Нажимает «Добавить».

Внутри автоматически создаются нужные части, связи и начальные настройки. Пользователь не видит технические названия и не соединяет ничего вручную.

Если для выбранного действия чего-то не хватает, плагин говорит об этом простыми словами. Например: «Для открытия нужна анимация крышки. Добавить простую?» Пользователь может согласиться или выбрать другое решение.

## 5. Настройка

Теперь показываются только настройки включённых возможностей.

Например, для сундука:
- Вместимость: 20 предметов.
- Время открытия: 1 секунда.
- Можно закрыть обратно: Да.
- Автоматически закрывать: Нет.
- Звук открытия: выбрать файл.

Параметры сгруппированы по смыслу. Рядом с непонятным параметром есть короткая подсказка. Стандартные значения уже выставлены, поэтому пользователь может сразу перейти к проверке.

Дополнительные настройки скрыты за кнопкой «Больше настроек».

## 6. Проверка

Пользователь нажимает большую кнопку **«Попробовать»**.

Открывается встроенный предпросмотр. В нём можно:
- нажать на сундук;
- открыть и закрыть его;
- добавить предметы в хранилище;
- проверить анимацию;
- включить отображение коллизий, если это нужно;
- сбросить тест и попробовать заново.

Предпросмотр использует текущий черновик, даже если пользователь ещё не сохранил его. Он не меняет оригинал и не создаёт отдельные тестовые сцены в проекте.

Если что-то не работает, плагин объясняет проблему обычными словами и предлагает действие для исправления.

## 7. Сохранение и добавление в игру

Пользователь нажимает **«Сохранить»**. Сундук появляется в библиотеке.

Затем пользователь нажимает **«Добавить в игру»** или перетаскивает карточку сундука в игровую сцену.

Сундук можно разместить мышью и сохранить сцену. Пользователю не нужно открывать исходные файлы или копировать технические ресурсы вручную.

Позже он может выбрать один конкретный сундук и изменить, например, вместимость только у него. Остальные сундуки и исходная карточка в библиотеке останутся прежними.

## 8. Если пользователь хочет изменить объект

Он открывает объект из библиотеки и меняет изображение, добавляет звук или новую возможность.

Плагин сохраняет изменения как новую версию. Размещённые экземпляры не перезаписываются без спроса.

Перед обновлением пользователь видит понятное сообщение: «Этот объект изменился. Обновить размещённые копии?» Можно выбрать нужные экземпляры и посмотреть, что изменится.

## 9. Тот же конструктор для других объектов

Пользователь создаёт другой объект тем же способом: внешний вид → возможности → настройки → попробовать → сохранить.

| Объект | Пример выбора возможностей |
|---|---|
| Подбираемый предмет | Можно подобрать, складывается в стопку |
| Ресурс | Получает урон, можно добыть, выдаёт предметы |
| Оружие | Можно экипировать, наносит урон, имеет прочность |
| Снаряд | Двигается, наносит урон, исчезает через время |
| NPC | Двигается, взаимодействует, получает урон, использует поведение |
| Животное | Двигается, издаёт звуки, реагирует на игрока |
| Механизм | Взаимодействует, переключает состояния, запускает другие объекты |
| Постройка | Имеет коллизии, взаимодействует с миром |
| Эффект | Проигрывает анимацию, звук или частицы |

Список — не ограничение. Пользователь может смешивать любые совместимые возможности.

## 10. Если пользователь хочет больше контроля

Кнопка **«Расширенные инструменты»** открывает техническую сторону объекта:
- дерево сцены и реальные узлы Godot;
- компоненты и их настройки;
- пользовательские свойства;
- события, состояния и связи;
- коллизии, точки крепления и точные параметры;
- пользовательский GDScript.

Пользователь может вернуться в простой режим в любой момент. Простое представление и расширенное представление редактируют один и тот же объект — это не две отдельные версии.

## 11. Как должны выглядеть ошибки

Вместо «Invalid NodePath»:
«Не удалось найти часть объекта. Выбери её заново».

Вместо «Missing dependency»:
«Для этой возможности нужна система здоровья. Добавить её?»

Вместо технической трассировки:
«Анимация не назначена. Выбери анимацию или создай простую».

У каждого сообщения есть понятная кнопка действия и ссылка «Подробнее» для опытного пользователя.

## 12. Обязательные правила интерфейса

- Простой режим включён по умолчанию.
- Пользователь видит большие карточки, понятные подписи и результат своих действий.
- На экране нет десятков параметров, не относящихся к текущей задаче.
- Не требуется выбирать корневой узел или вручную соединять компоненты.
- ID, ссылки и технические зависимости создаются автоматически.
- Любое автоматическое изменение можно отменить.
- Предпросмотр не требует создания тестовой сцены.
- Стандартные технические инструменты доступны, но не навязываются.
- Создание разных объектов проходит через одинаковые шаги.

## 13. Проверка сценария перед выпуском

Приёмочные проверки нужно провести на нескольких разных объектах: простом подбираемом предмете, интерактивном механизме, оружии или снаряде, персонаже/NPC и составном объекте.

Главный вопрос проверки: сможет ли новичок создать и разместить объект без документации, без написания кода и без необходимости открывать техническую структуру?

Если для обычной операции приходится объяснять пользователю Component Binding, NodePath или Scene Tree — простой сценарий ещё не готов.

## Сценарий: найти и пакетно добавить возможности

1. Пользователь открывает «Каталог возможностей» из рабочего пространства текущего объекта.
2. Каталог сразу учитывает категорию/профиль объекта и уже установленные возможности, но не ограничивает ими выбор.
3. Пользователь вводит запрос обычным языком либо открывает рекомендации, категорию, избранное, недавние или набор.
4. Пользователь нажимает несколько карточек. Выбор сохраняется при любом поиске, фильтрации и переходах по связям.
5. При фокусе на карточке каталог показывает объяснимые отношения: обязательные, рекомендуемые, расширяющие, альтернативные, конфликтующие и связанные.
6. Пользователь открывает панель выбранного, при необходимости снимает отдельные пункты и нажимает «Добавить выбранные (N)».
7. Конструктор показывает общий план, включая автоматически необходимые зависимости, уже существующие записи и конфликты.
8. Пользователь подтверждает. Все изменения применяются одной атомарной операцией и одним пунктом Undo/Redo.
9. При неуспехе объект остаётся без частично применённых изменений. Пользователь получает объяснение и варианты исправления.

## Сценарий: визуальная или иная не-поведенческая возможность

1. Пользователь выбирает возможность из раздела внешнего вида, анимации, звука, физики или другого направления.
2. Каталог показывает, где она действует: при редактировании, во время игры, на обоих этапах или только задаёт данные.
3. Object Builder открывает подходящую форму настройки и меняет нужные ресурсы/узлы/данные без требования создавать runtime-компонент, если он не нужен.
4. Preview показывает результат, когда это применимо. Для editor-only возможности результат отражается непосредственно в редакторе объекта.
5. Сохранение и Undo/Redo работают по тем же общим правилам, что и для поведенческих возможностей.
