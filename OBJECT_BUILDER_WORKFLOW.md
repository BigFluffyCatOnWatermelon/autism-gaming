# Object Builder — сценарии взаимодействия с плагином

Документ описывает, как пользователь должен работать с Object Builder. Он дополняет OBJECT_BUILDER_DESIGN_SPEC.md и авторскую ROADMAP.md. Все сценарии используют одну универсальную архитектуру; примеры не создают специальные ветки кода под конкретные виды объектов.

## 1. Что пользователь видит при открытии плагина

Пользователь нажимает главную вкладку Object Builder.

Открывается раздел «Библиотека». На экране:
- слева дерево категорий, поиск, избранное, недавние и коллекции;
- в центре сетка или список объектов;
- справа карточка выбранного объекта с preview, описанием, тегами, версией и компонентами;
- сверху команды «Создать», «Импортировать», переключение режима сетка/список и фильтры;
- снизу, если нужно, журнал и диагностика.

Никакой объект не выбирается автоматически. Пользователь может открыть существующий, создать новый или импортировать сцену.

## 2. Создание любого нового объекта

### Шаг 1. Начать создание

Нажать «Создать». Мастер предлагает:
- пустой объект;
- объект из шаблона;
- копию существующего объекта;
- импорт сцены Godot;
- импорт пакета объекта.

Все варианты ведут в один и тот же Object Editor и формат Definition + Scene.

### Шаг 2. Выбрать стартовый профиль или отказаться от него

Пользователь выбирает профиль, например «Общий объект», «Ресурс», «Персонаж», «Снаряд», «Контейнер», «Постройка» или пользовательский. Также есть «Без профиля».

Профиль сообщает, что он предлагает: корневой узел, стартовые свойства, компоненты, структуру сцены. Пользователь может изменить каждую рекомендацию, удалить предложенный компонент и добавить любой другой. Профиль не ограничивает дальнейшие действия.

### Шаг 3. Заполнить идентичность

Пользователь задаёт название, категорию/подкатегорию, теги, описание и иконку. Постоянный ID генерируется автоматически. Если пользователь хочет изменить его после появления ссылок, выполняется отдельная безопасная процедура переименования ID.

### Шаг 4. Выбрать техническую основу

Мастер предлагает подходящий root-узел и объясняет его назначение. Пользователь может выбрать другой поддерживаемый тип. Не нужно знать весь список классов Godot наизусть: рядом есть поиск и короткие подсказки.

После нажатия «Создать черновик» открывается редактор объекта.

## 3. Рабочий экран объекта

Верхняя панель: имя документа, несохранённые изменения, Undo/Redo, Save, Validate, Preview, Add to Scene.

Слева:
- вкладка «Структура» — дерево узлов;
- вкладка «Компоненты» — список компонентов выбранного узла;
- кнопка «Добавить узел»;
- кнопка «Добавить компонент».

В центре:
- 2D-поле с объектом;
- инструменты Select/Move/Rotate/Scale;
- переключатели отображения спрайтов, коллизий, sockets, pivots, hitbox/hurtbox;
- масштабирование и перемещение камеры.

Справа:
- контекстный инспектор;
- только параметры выбранного объекта, узла, компонента или свойства;
- стандартные свойства Godot открываются в штатном Inspector, а не дублируются в собственной форме.

Внизу:
- ошибки, предупреждения, ресурсы/зависимости, события и журнал;
- панель скрыта, пока нет необходимости.

Пользователь может скрыть боковые зоны и сохранить свою раскладку.

## 4. Полный сценарий: интерактивный сундук

Сундук — пример прохождения всех основных систем. Не следует делать сундук особым встроенным типом.

### 4.1 Создать
1. Библиотека → Создать → Пустой объект.
2. Профиль «Интерактивный объект» (или «Без профиля»).
3. Категория «Интерактивные / Контейнеры».
4. Название «Сундук», ID автоматически создан.
5. Выбрать подходящий 2D root.
6. Нажать «Создать черновик».

### 4.2 Собрать визуальную часть
1. В дереве выбрать корень и нажать «Добавить узел».
2. Добавить Sprite2D, назначить текстуру сундука.
3. Настроить Texture/Region/HFrames/VFrames/Frame, Offset, Scale и Z.
4. Добавить отдельный Sprite2D для крышки, чтобы её можно было анимировать отдельно.
5. Установить pivot крышки и проверить отображение в центре.
6. Переименовать узлы осмысленно: Body, Lid, Shadow.

### 4.3 Настроить физику
1. Добавить StaticBody2D или использовать подходящий корневой узел.
2. Добавить несколько CollisionShape2D для корпуса и крышки.
3. Включить режим «Коллизии».
4. Отредактировать прямоугольник/полигон визуально.
5. Назначить Collision Layer и Mask.
6. Убедиться, что крышка не создаёт лишний блокирующий контур, если он ей не нужен.

### 4.4 Добавить собственные свойства
Создать:
- capacity — Integer, базовая вместимость.
- locked — Boolean, состояние замка.
- key_id — String или Enum, ID подходящего ключа.
- open_duration — Float, время открытия.

Для каждого поля указать описание, группу, default и диапазон. Отображаемое имя можно менять, property_id остаётся неизменным.

### 4.5 Подключить компоненты
1. Выбрать узел взаимодействия и добавить Interactable.
2. Выбрать узел-хранилище и добавить Container.
3. Добавить Lock, если сундук должен открываться ключом.
4. Привязать Lock к property_id locked и key_id.
5. Добавить Audio к узлу звука, назначить звуки открытия и закрытия.
6. Проверить зависимости в каталоге. Если компонент требует другой, интерфейс объясняет почему и предлагает добавить его явно.

### 4.6 Состояния и события
1. Создать состояния Closed и Open.
2. Указать, что меняется: трансформ крышки, анимация, доступность взаимодействия.
3. В редакторе связей создать событие On Interact.
4. Добавить условие: Locked?
5. Если да — проверить наличие ключа.
6. Если условие выполнено — перейти в Open, запустить анимацию и звук.
7. При повторном взаимодействии вернуть Closed.

### 4.7 Preview
1. Нажать Preview.
2. Проверить статичный вид, масштаб и точку pivot.
3. Включить отображение коллизий.
4. Переключить Closed/Open.
5. Проверить блокировку без ключа и открытие с ключом.
6. Проверить звук, анимацию и вместимость.
7. Сбросить preview-состояние.

Preview создаёт временный экземпляр черновика. Он не помещает объект в World и не меняет библиотечные данные без сохранения.

### 4.8 Проверка и сохранение
1. Нажать Validate.
2. Ошибки и предупреждения показываются в нижней панели.
3. Нажать на ошибку — редактор выбирает проблемный узел/поле.
4. Исправить отсутствующую ссылку или несовместимость.
5. Нажать Ctrl+S.
6. Definition, Scene, preview и индекс библиотеки обновляются; при перезаписи создаётся резервная копия.

### 4.9 Добавление в игровой мир
1. Нажать Add to Scene.
2. Выбрать открытую World и группу назначения.
3. Разместить сундук в нужной позиции.
4. Выбрать конкретный экземпляр и изменить его локальное свойство, например capacity = 24.
5. Базовый объект в библиотеке остаётся с capacity = 12.
6. При будущем обновлении Definition пользователь выбирает, какие экземпляры обновить, видит список изменений и разрешает конфликты.

## 5. Дополнительные сценарии

### Импорт существующей сцены
1. Нажать «Импортировать сцену».
2. Выбрать PackedScene.
3. Плагин анализирует дерево узлов, ресурсы, скрипты, связи и потенциальные конфликты.
4. Пользователь выбирает, импортировать ли исходную структуру целиком или создать копию.
5. Плагин формирует Definition и библиотечную копию Scene.
6. Оригинальный файл не перезаписывается.
7. В диагностике показываются нераспознанные пользовательские скрипты и ресурсы. Неизвестное содержимое сохраняется.

### Создание из шаблона
1. Открыть «Шаблоны».
2. Выбрать шаблон и просмотреть структуру/компоненты.
3. Нажать «Создать объект».
4. Мастер запрашивает новое имя, ID и категорию.
5. Создаётся независимая копия Definition/Scene. Шаблон не изменяется.

### Дублирование
1. В библиотеке выбрать объект.
2. Нажать «Дублировать».
3. Ввести имя и категорию новой копии.
4. Новый объект получает новый ID.
5. Внутренние ссылки и зависимости обновляются по правилам копирования; исходник остаётся неизменным.

### Редактирование существующего объекта
1. Открыть объект из библиотеки.
2. Изменить структуру, компоненты или свойства.
3. Просмотреть diff изменений.
4. Нажать Validate и Save.
5. Размещённые экземпляры не меняются автоматически.

### Обновление размещённых экземпляров
1. Плагин видит, что Definition новее базовой версии экземпляра.
2. Пользователь открывает список затронутых экземпляров.
3. Видит изменения полей/компонентов и конфликтующие overrides.
4. Выбирает экземпляры и правила применения.
5. Подтверждает обновление после создания backup.
6. Может откатить результат.

## 6. Как должны вести себя панели и команды

- Поиск доступен в библиотеке и каталогах компонентов/ресурсов.
- Командная палитра находит команды, узлы, свойства, компоненты и шаблоны.
- Все изменения структуры и свойств имеют Undo/Redo.
- Ctrl+S сохраняет текущий объект и его сцену.
- Escape закрывает контекстное меню/диалог, но не отменяет незаписанную работу.
- Удаление узла/компонента показывает последствия, если на него есть ссылки.
- Сложные настройки имеют описание и подсказку.
- Основные параметры видны сразу; расширенные и экспертные раскрываются отдельно.
- Панели можно свернуть, изменить ширину и восстановить рабочую раскладку.
- Статус сохранения, ошибки и зависимости видны, но не занимают постоянную большую часть экрана.

## 7. Разные объекты — один сценарий инструментария

**Снаряд:** профиль может предложить Area2D, Sprite2D, CollisionShape2D, Projectile и Lifetime. Пользователь свободно меняет состав, добавляет Audio/Effects и настраивает попадание.

**Персонаж/NPC:** профиль может предложить CharacterBody2D, визуальные части, коллизию, Health, Movement, AI, Inventory, Attack и State Machine. Любой компонент можно удалить или перенести на другой узел.

**Оружие:** структура спрайтов и sockets, компоненты Attack, Durability, ProjectileSpawner, Audio; параметры урона, скорости, дистанции и типа боеприпаса.

**Станок:** StaticBody2D, визуальная анимация, Interactable, Crafting, Container/Inventory, рецепты и аудио.

Это только стартовые пресеты. Пользователь может смешать совместимые возможности и создать новый вид объекта без изменения центрального кода.

## 8. Признак хорошего сценария

Пользователь не должен думать: «Какой специальный редактор нужен для этого типа объекта?». Он должен думать: «Какие узлы, данные и возможности нужны моему объекту?».

Object Builder показывает подходящие инструменты по текущему выбору и не ограничивает дальнейшую сборку искусственной категорией.
